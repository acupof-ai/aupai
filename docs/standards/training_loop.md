# 训练闭环：从读数到下一版配比

**结论先行：这个闭环今天有一个测量缺口，它比配比本身更要紧。** 8B→16B 这
8.258B token 里，**77% 花在了归因不到的地方**——3.340B 在两个更名熄灯的域，
2.984B 在被权重闸拒判的 code_rp1t。剩下 23% 才是我们能说出"这些 token 教了
什么"的部分。

先修可归因性，再谈配比。理由在第 1 节。

## 1. 归因账：8.258B token 里有多少是可读的

区间 7.799B（step8500）→ 16.056B（step17500），跨阶段边界，其中 stage-1
7.139B、stage-2 1.118B。每个角色在这段区间里实际吃到的自有 token，按
w1/w2 分段加权：

| 角色 | 区间内自有 token | Δloss | **nat / B 自有 token** | 判决 |
|---|---|---|---|---|
| wiki_chat | 0.055B | +0.1571 | **2.8541** | moved |
| textbook_30b | 0.275B | +0.1382 | **0.5024** | moved |
| zh_web | 0.908B | +0.1504 | **0.1657** | moved |
| cot | 0.696B | +0.0821 | 0.1180 | floor |
| code_rp1t | 2.984B | +0.0483 | 0.0162 | **闸拒判** |
| en_c4 | 1.673B | — | — | **熄灯（更名）** |
| math_owm | 1.667B | — | — | **熄灯（更名）** |

最后一列是这份文档的核心量：**每 B 自有 token 买到多少 nat**。它把"这个域
值不值"从占比之争变成一个可比的数。

三件事从这张表里掉出来：

**一、跨度 176 倍，而它不支持任何读法。** wiki_chat 每 B 自有 token 买
2.85 nat，code_rp1t 买 0.0162。它含着两个未分离的东西：域在自身曲线上的
位置，以及第 6 节那个未测的迁移偏差。

**我初稿写"唯一读法是 code_rp1t 吃饱、wiki_chat 陡峭，两种解释下都成立"，
这是错的**（44 审出）。在迁移解释下排序可以任意——一个域的 loss 大量由别的
域的 token 驱动时，它自己的 nat/B 低不意味着它饱和。"吃饱"恰恰是第 6 节
禁止的那种跨角色读法，我在给出禁令的同一份文档里走私了一次。

角色内的证据也没有：15B 的 +0.069 与 16B 的 +0.0483 打在不同的头上，不可比。
**这个跨度是一个待解释的观察，不是一个结论。**

**二、这个量本身会随 token 数下降，而且我们的估计偏乐观。** loss 走幂律
$L(D) \approx A D^{-\alpha}$，凸性直接保证割线斜率 ≥ 区间右端瞬时斜率，
**方向不依赖 α**。幅度依赖：α = 0.05–0.1 时，token 翻一倍（r ≈ 2）右端瞬时
斜率是割线的 0.70–0.71，翻三倍是 0.57–0.59，即速率高估约 1.43×。

**r ≈ 2 是一个假设**：各域在这个区间里的累计 token 增幅并不相同，所以逐域
的实际 r 不是 2。但凸性保证了方向对每个域都成立，**下界性质安全，只有幅度
按域而异**。

**三、77% 的支出没有读数。** 这是下一节的全部内容。

## 2. 缺口：两个熄灯域和一个被拒判的域

| 类别 | 域 | 区间内 token | 为什么读不出 | 可逆吗 |
|---|---|---|---|---|
| 更名熄灯 | en_c4、math_owm | 3.340B | stage 2 重建为 `*_stage2`，held-out 文本非同一批（prereg §7.5） | **未建，非不可逆**（见下） |
| 权重闸拒判 | code_rp1t | 2.984B | w 0.372→0.293 = 0.79×，超 5% 容差（§7.1） | 阶段内可读 |

两者性质不同，处置也不同。

**更名域损失的正是最贵的两块。** en_c4 和 math_owm 在这段区间里合计
3.340B token，占全部支出的 40%，而我们对这 40% 的能力效应**一个数都没有**。

**但这是"未建"，不是"不可逆"**（44 审出，pod 核实）。stage-1 的 val 切片是
`seqs[:n_val]`（train.py:1750-1751），由语料字节 + `corpus_seed` + tokenizer
确定性地决定，而 en_c4（166 shards）与 math_owm（127 shards）的 stage-1 语料
今天仍在 pod 上。**这份切片今天可以重建。** 它能不能用取决于一次验证：按
prereg §7.2.2 拿它的哈希对 stage-2 语料重探，命中 = 污染 = 该角色的读数真死。
**未验证之前，"不可逆"这个词不该出现**——它把一件没做的事说成一件做不到的
事，而两者的下一步动作完全不同。

**这条要写进以后每一次语料重建的决策里**：重建一个域 = 在**重建的那一刻**
放弃它的跨阶段 per-role 读数，除非同时冻结一份切片。事后能不能补回来取决于
旧语料还在不在、以及污染重探过不过——en_c4 和 math_owm 这次两个条件都还
可能满足，但那是运气，不是设计。以前这条是隐含的，现在它有价了——3.340B
token 的可归因性，而买它的成本是一份 4000 行的固定文本。

**code_rp1t 是可恢复的，走阶段内。** 16B→24B→30B 同头同权重同语料字节，
7 个角色全可读，不触发 §7.1/§7.2。**24B 里程碑是这条闭环第一次真正闭合的
地方**——按 917,504 tok/step，24B 在绝对 step 26,158，不是 24,000（step
24,000 = 22.0B，44 审出）。

## 3. 一个配比改动要多大才测得出

用第 1 节的观测速率，反推移动一个 0.1176 nat floor 需要的自有 token，
再按 stage-2 权重折算成 run 长度：

| 角色 | nat/B 自有 | 移动一个 floor 需自有 token | w2 | 折合 run 长度 |
|---|---|---|---|---|
| wiki_chat | 2.8541 | 0.041B | 0.00664 | 6.2B |
| zh_web | 0.1657 | 0.710B | 0.10955 | 6.5B |
| textbook_30b | 0.5024 | 0.234B | 0.03320 | 7.1B |
| cot | 0.1180 | 0.997B | 0.08069 | 12.4B |
| code_rp1t | 0.0162 | 7.259B | 0.29330 | **24.8B** |

**右列是下界**（第 1 节第二点），且假设加 token 是唯一的杠杆。
**code_rp1t 那一行除外**：它的 Δloss 本身在 floor 之下且被权重闸拒判，
所以 24.8B 是面值外推，不是下界。见下。

这张表回答 fb 问的第三个问题——**什么测量能说明课程改动起作用了**——的
方式是先划掉大半个选项空间：

- **我们剩下的预算是 30B − 16B = 14B。** 在这 14B 里，一次配比改动只有在
  它作用的角色**折合 run 长度小于 14B** 时才可能读出效应。zh_web、
  textbook_30b、wiki_chat 在范围内；cot 勉强；**code_rp1t 不在**。
- **所以"通过加大 code 占比改善代码能力"在剩余预算里不可测。** 不是它没
  效果，是这个 run 判不了。判它要靠生成指标（code-500），而 code-500 在
  n=500 上的地板是 12.6pt，当前读数是 0.0——**两个仪器同时够不着**。
- **cot 的 12.4B"勉强"要打折**：它对迁移膨胀最敏感（推理数据的 loss 受
  math 与 code 的 token 影响大），真实成本可能出预算。不要按"勉强够"规划。

**24.8B 是点估计，不是下界**（44 审出，采纳）。code_rp1t 的 Δ = +0.0483
在 floor 之下，是一个双侧陈述：Δ 的区间约 [0, 0.166]，对应速率区间含点估计
的 3 倍，成本可以低到 ~7B，**不能排除小于 14B**。它还叠了一层混杂：该角色
权重降了 21%，Δ 系统性偏低，成本因此偏高——方向对结论有利，但那是混杂不是
证据。

保留 24.8B 的理由是**量级**而非界：点估计是剩余预算的 1.78 倍，且第二台
仪器（code-500）独立地够不着。fb 的裁决站在这两条上，不站在"下界"上。

### 三条不该做的

| 做法 | 为什么不 |
|---|---|
| 用 8B→16B 的 per-role 差判 stage-2 配比 | 三个承载配比论点的角色（math 加、code/en 减）恰好全部不可读（prereg §7.1 推论一） |
| 在 30B 前再改一次配比来"试" | 一次改动要 6–25B 才能读出；14B 预算里改两次 = 两个都读不出，且互相混杂 |
| 把 nat/B 当成域的固有属性 | 它是**当前 token 数下**的局部斜率，随该域已花 token 单调下降，且我们的速率估计高估约 1.43×（r≈2 时） |

## 4. 三轨在这个闭环里各回答什么

prereg §7.5 立的三轨，落到"下一版配比怎么定"这件事上：

| 轨 | 回答的问题 | 16B 时的状态 | 什么时候能用 |
|---|---|---|---|
| 进度（阶段内） | 这些 token 教会了什么 | 未启动（stage-2 内首个里程碑是 24B） | **24B（step 26,158）**，7 角色全读 |
| 进度（跨阶段） | 复用域跨越阶段后学到了什么 | 5 域可读，1 被闸拒（code_rp1t） | 已有，本文第 1 节 |
| 保留（OOD，标注） | 更名域有没有灾难性遗忘 | 未跑，需先做 holdout 重探 | 30B 一次性重打分 |
| 组成 | stage-2 重建值不值 | **per-role 回答不了** | 聚合趋势 + 保留轨 + 语料级事实 |

**注意最后一行。** "重建值不值"是这次 stage-2 最想知道的事，而三轨里没有
一轨单独回答它——按 3.24B floor 的同一逻辑，不可归因的比较不如缺席。

## 5. 下一版配比：能提的三条，和它们的验证

给 stage 3 / 下一个 run，按"可测性"而不是"想要什么"排序：

| # | 改动 | 依据 | 验证它的测量 | 可测吗 |
|---|---|---|---|---|
| 1 | 语料重建时保留一份 stage-1 命名的 held-out 切片 | 本文第 2 节：3.340B token 的可归因性，成本约 4000 行文本 | 下次重建后跨阶段 per-role 不熄灯 | **是，且几乎免费** |
| 2 | 权重变化控制在 5% 容差内，除非有明确的配比论点 | §7.1：超容差 = 该角色跨阶段拒判；code_rp1t 的 2.984B 就这么丢的 | 闸不再拒判该角色 | **是** |
| 3 | 小域（wiki_chat、textbook_30b）加量 | 第 3 节：折合 run 长度 6–7B，在 14B 预算内 | 阶段内 per-role，24B→30B | **是，但只有一次机会** |

**1 和 2 是测量基建，不是配比决策。** 它们的收益是让第 3 类改动在下一个 run
里判得出来，而这是当前最短的那块板。

### 5.1 第 1 条落地为 build 期闸口，不是惯例（fb 裁定 2026-09-01）

**任何重命名或替换域的语料重建，必须在打戳之前产出一份阶段命名的冻结
holdout 切片，缺失则 build 拒绝。** 归 3b（owns `build_corpus`，settle guard
已在该路径）。

**"冻结"必须包含排除在 near-dedup post-pass 之外**（44 审出）：该 pass 会
就地重写行（见 `docs/lessons/near_dedup_stage2_postpass.md`），一份被就地
改过的切片不再是它打戳时的那份文本，闸也就白设了。

写成惯例，它活到第一次赶工重建为止；写成拒绝，它活下来。3.340B 是没有它的
价钱，也是这个闸口的全部论据。

### 5.2 code 占比：本 run 内不可判，且必须如此标注（fb 裁定 2026-09-01）

第 3 节已给理由——移动它的 floor 要 24.8B run，剩余预算 14B；code-500 自身
地板 12.6pt，当前读数 0.0。**两个仪器同时够不着。**

这不是说不该调。是说**这个 run 里调它拿不到证据**：若要调，依据是 §6.3 的
外部证据（470M 上 25% 最优于知识、374M 上 40–50% 最优于算术），且它是一个
**无读数的决策**，必须以这个措辞交给用户，不得以"我们调了 code 占比"的形式
出现在任何结论里。

## 6. 学习增益度量的适用范围

第 1 节的 nat/B 把 Δloss 除以该域自有 token，隐含**该域的 loss 只由该域的
token 驱动**。这是错的：域间有迁移，code 的 token 会改善 math 的 loss。

**每个数字都因此偏大**：分母只算自有 token，分子含了全部来源的贡献。偏差
幅度按角色不同——迁移进项多的角色偏得更多——而迁移矩阵没测过，也不打算在
这个 run 里测（要 7 个单域消融）。**所以不能假定排序被保住。**

**用法上的限制**：nat/B 只用于**同一角色跨时间**的比较（这个域还陡不陡），
不用于**跨角色**的资源分配（谁更值）。第 3 节用的是前者，第 1 节的 176 倍
跨度是描述而不是排序依据。

**写下限制不等于遵守它。** 本节的限制写完之后，第 1 节仍然走私了一次跨角色
读法（"code_rp1t 吃饱"），由 44 审出；同一天 tilerl 写完"聚合量不界定分量"
的更正，三十分钟后又把一个推算值当约束报了出去。**今天写下的每一条规则都
来自它已经被违反的那个案例，没有一条被预防性地用在下一个同形案例上。**
所以这些限制要落成可对着具体数字检查的测试，而不是原则——原则对不上任何
东西，测试对得上一个数。

## 7. 作废条件

- **24B 阶段内读数出来**：第 1 节的速率全部重算，跨阶段口径退居次要。
- **迁移矩阵被测**：第 6 节的限制解除，nat/B 可用于跨角色比较。
- **α 被拟合**：第 1 节的 0.70× 修正从"典型范围"变成本 run 的实测值，
  第 3 节的下界变成估计值。

三条里没有一条需要新的基础设施，都是已有读数多跑几个点。
