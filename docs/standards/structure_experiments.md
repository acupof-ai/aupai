# 四个 run，200M@1B：先填 AttnRes 的空白，再试按块类分 lr

**这页的规矩：一个 run 一个变量，读数在开跑前写死，两种结果各对应一个动作。**
没有"看情况再说"的分支——那等于没有预注册。

## 0. 基线事实（读出来的，不是推的）

从 `ckpt_p500m_20b_0902.pt.step2500` 读：

| 事实 | 值 | 怎么读到 |
|---|---|---|
| 块布局 | **32 块 = 24 KDA + 8 MLA，MLA 在 3/7/11/…/31** | `blocks.<i>.mixer.A_log` 在不在 |
| KDA 参数占比 | mixer 126.2M + ffn 226.5M = **352.7M（块参数的 67%）** | 2D 权重逐个求和 |
| 每块参数 | KDA 14.71M / MLA 13.38M（**近乎相等**） | 同上 |
| KDA/MLA 范数增长比 | **3.74× → 3.43× → 7.96×**（三个区间，**不稳定，见 §3**） | `scripts/ckpt_health.py` 按块类拆 |
| 张量范数中位 | **KDA 42.88 > MLA 33.77** | 同上 |
| FP8 覆盖 | 块内 linear **全覆盖**；只有 LM head 不走（6.38%，已判决 no-ship） | `_fp8_ok` 逐个核 |

**那个 3.4–3.7× 不是小分母造成的**：如果 KDA 权重更小，同样的绝对更新会显示成更大的相对增长。
**实测 KDA 范数更大（42.88 vs 33.77），每块参数量也几乎相等**，所以两个最可能的伪影方向都排除了。
KDA 块**又大又长得更快**，这是 R3-lr 的动机（§3）。

## 1. 规模与预算：四个 run，200M@1B，排在 p300m 之后

**b0-12 的形状，三条都按本页算出的数落定（fb 裁定 2026-09-02）：**

**一、实验层 = 200M@1B，100M 这一级砍掉。**
吞吐用 **72K tok/s/gpu，30% MFU**——`facts/efficiency.json#eff.microbatch_32_oom`
里 t52 pair1（2026-08-31）的**基线臂 batch 16 accum 2**，seq 4096、fp8、206M/L12/d1024，
**p200m_4b 启动行的同一个配置**（`stop_window` 写的是 `--batch 16 --accum 2`）。

**本页前一版用的是 `eff.fb_mfu` 的 73K「batch 32」，那个 batch 是错的**（fb 更正
2026-09-02）：那条 fact 的 source 是 "aupai-fb briefing"，**batch 32 从来没被量过，
而且第二天就被实测推翻**——t52 量到 b32a1 在 93.8/95.2 GB OOM，判决是「保持 micro-batch 16」。
**我把一句 briefing 读成了一个被测过的配置**，然后拿它去给别人的 OOM 归因（见 §6 末）。

| 方案 | 卡时/run | 吞吐来源 |
|---|---|---|
| **200M @1B（采用）** | **3.86** | **实测**（`eff.microbatch_32_oom` 基线臂，同配置） |
| 100M @2B，72K | 7.7 | 外推 |
| 100M @2B，144K（盈亏平衡） | 3.86 | 外推 |

**100M 要便宜过 200M@1B，得跑到 144K tok/s/gpu = 实测值的 2.00 倍**，没有依据。

**这个 2.00 倍不依赖吞吐的具体值，这是本节唯一稳的地方**：200M 跑 1B、100M 跑 2B，
**token 数差 2 倍，所以盈亏平衡永远是「2 倍吞吐」，不论 T 是 72K 还是 73K 还是别的**。
73K → 72K 只把绝对卡时挪了 1.4%（3.81 → 3.86），**三条结论一条都没动**。
而 200M 本来就是验收所在那一级，**省掉"能否外推到 200M"这一跳**。

**启动成本不会翻转这个结论，它在等式两边都出现。** 令启动秒数为 S：

```
200M@1B 墙钟 = 1e9/(8×72K) + S = 1,736 + S
100M@2B 墙钟 = 2e9/(8×T)   + S
100M 更便宜  ⟺  2e9/(8T) < 1,736  ⟺  T > 144K = 2×72K
```

**S 精确抵消。** 两个方案跑的是同一份代码、同一条缓存读路径，
**启动成本近似相等，所以它改变两边的绝对值而不改变谁更便宜**。
**唯一的翻转杠杆是 100M 自己的吞吐要到 144K**——实测值的两倍，而「两倍」这个
倍数由 token 比 2:1 决定，换任何吞吐值都不变。
（`--warmup` 也不是杠杆：它只改 lr 表，每步 token 数不变，见下。）
**"S 大到某个值就翻转"这个形状不成立**，因为它默认 S 只加在一边。

**二、硬上限四个 run。**

| run | 问题 | 配置（L12 d1024、1B token） |
|---|---|---|
| **B0** | 三问共用基线 | 3 MLA + 9 KDA、AttnRes ON、单一 base lr |
| **B0-seed2** | 定 sigma（**不可砍**） | 同 B0 换 seed |
| **R2-off** | （2）AttnRes | AttnRes OFF |
| **R3-lr** | （3a）分 lr | KDA 块 lr × 0.28 |

**4 × 3.86 = 15.4 卡时 = 八卡 1.93 小时。** 参照：
**这正好等于 p200m_4b 生产 run 本身的成本（4B token 同一吞吐 = 15.4 卡时），
是 p200m + p300m 合计（38.6 卡时）的 40%。**
**排在 p300m 之后串行跑**，不与生产 run 抢卡。

### 四个臂的旋钮：照 p200m 启动行，只改 `--warmup`

**其余旋钮全部照 `stop_window_2026-09-02.md` 的 p200m 启动行**
（`--dim 1024 --layers 12 --heads 8 --ffn_hidden 3072 --batch 16 --accum 2
--no-grad_ckpt --lr_scale 1.0 --warmdown 0.1 --anneal_frac 0 --save_every 500`），
**batch 16 accum 2 而不是 32×1**：`eff.microbatch_32_oom` 实测 b32a1 在 93.8/95.2 GB
OOM，每步 token 数两者相同（16×2 = 32×1），**所以这不是一个可选的旋钮，是唯一装得下的写法**。
mix 是 500M 组成缩到 1B。**`--warmup` 是唯一要改的**（fb 定）。

**warmup 不影响成本，只影响 lr 表**——它改 lr 乘数（`train.py:1985`），
**每步 token 数不变**，所以它进这一节是可读性问题不是预算问题。
**（本页上一版把它当成摊薄吞吐的原因之一，那是错的，fb 更正。）**

**`--warmup 100` 有一个副作用要写明**：`train.py:1160` 的 Muon 动量 ramp 是
`0.85 + 0.10 × min(1, step/150)`，**一个在 L=12 上拟合、之后没再动过的常数**。
warmup 结束时动量走到哪里，随 warmup 值大幅移动：

| `--warmup` | 占 954 步 | warmup 结束时的动量 | 动量 ramp 进度 |
|---|---|---|---|
| 20（`Cfg` 默认） | 2.1% | 0.8633 | 13% |
| **100（本次采用）** | **10.5%** | **0.9167** | **67%** |
| 300（p200m 生产值） | 31.4% | 0.9500 | 100% |

**100 把两个常数的相对关系换了一个位置**：默认 20 下 lr 满值时动量才走 13%
（`docs/lessons/warmup_momentum_interaction.md` 记的就是这个），
**100 下变成 67%**。**这不构成反对 100 的理由**——它比 300 更接近生产 run 的
warmup 占比（生产 300/3815 = 7.9%，本次 100/954 = 10.5%，**按占比匹配应取 75**），
而且 `eff.warmup_absolute_not_fractional` 的证据是**单侧的**（2/3/20 三个点单调，
**20 以上从未测过**），所以 100 落在一个没有读数的区间里。

**含义：四个臂之间可比（同一个 warmup），但它们与 p200m 生产 run 的早期曲线不可比。**
**别把臂的前 100 步 loss 和生产 run 的前 300 步对着看**——lr 表和动量状态都不同。

**（1）比例延后，理由是空白硬度而不是重要性**：（2）的 OFF 臂在任何深度都没有配对读数
（§3），（3a）有 3.4–3.7× 的实测动机（§0），**（1）两者都没有**——现状 3:1 已经有
20B token 的运行记录，而"更稀疏会不会更好"目前只是猜想，没有任何读数指向它。
**5:1 作为 R1 的 B 臂保留在 §2 待用**，等（2）（3a）的结论回来再排。

**B0-seed2 不可砍**：0.02 nat 的门是 500M/0.2B 的 sigma-hat 0.0516 换算的，
**200M/1B 的 seed 方差没测过**。没有它，R2-off 和 R3-lr 的胜负都读不出来，
**那三个 run 一起白跑**。**两个 seed 是这个计划的最小可读单位，不是余量。**

**三、`7:1` 在这个阶梯上不存在。** MLA 数必须是整数：

| L=12（p200m） | 可达比例 |
|---|---|
| 2 MLA + 10 KDA | **5:1** |
| **3 MLA + 9 KDA** | **3:1（现状）** |
| 4 MLA + 8 KDA | 2:1 |
| 6 MLA + 6 KDA | 1:1 |

**7:1 在 L=12 要 1.5 个 MLA，在 L=18 要 2.25 个。** 本页上一版的 7:1 是从 500M 的
L=32 抄来的（那里 4 MLA 刚好 7:1）——**把一个只在 L=32 成立的配置写成了整个阶梯的臂**。

### "现状 3:1" 只对 L12 和 L32 说话（fb 指定本节由 b0 写明）

| run | L | 布局 | 比例 |
|---|---|---|---|
| p200m_4b | 12 | 3 MLA + 9 KDA | **3:1** |
| p300m_6b | 18 | **4 MLA + 14 KDA** | **3.5:1** |
| p500m（已停） | 32 | 8 MLA + 24 KDA | **3:1** |

**p300m 保持 L18**（用户定的参数级，`stop_window_2026-09-02.md`），
**所以它的比例是 3.5:1，不是 3:1**。**本页所有"现状 3:1"只指 L12 和 L32。**
含义有两条，都要写进任何采用比例结论的 recipe：

1. **结构实验在 L12 上跑，结论按比例往 L18 搬时不能照抄 MLA 个数。**
   若（1）将来定出 5:1，L=18 上 5:1 要 3 个 MLA（15 KDA），**不是把 4 改成 3 就完事**——
   MLA 的**位置**也要按新比例重排。
2. **p300m 今天的 3.5:1 不是任何实验的结论，是 L18 下 4 个 MLA 的算术结果。**
   把它当成"现状比例"会把一个取整副产品读成一个决定。

**上一版的成本报错 8 倍，机制值得记**：写的是
`2e9/(30e3×8) ≈ 8,333 卡秒 ≈ 2.3 卡时/run`。**8,333 是墙钟秒，不是卡秒**——
除以 8 卡之后再叫卡时，**等于把"卡时"里的"卡"约掉了**。
**卡时 = 墙钟 × 卡数**，同一个 30K 下真值 18.5 卡时。
**错不在 30K 那个外推（只差 2.4×），在单位。** 两个错叠起来报出 2.3 对着真实 7.6，
低报 3.3 倍——**而正是这个低报让"六个 100M run"看起来可接受，掩盖了第一条结论。**
（已收进 shape 表。）

## 2. R2-off：AttnRes 开关 —— **四个 run 里空白最硬的一个**

**问的数**：val loss 与 tok/s/gpu 的配对。
**A 臂 = AttnRes ON（现状 Full）** = B0，**B 臂 = OFF** = R2-off。

**这是真实空白，不是重复测量**：`facts/efficiency.json` 里所有 AttnRes 读数
（`eff.grad_ckpt_inverts_with_depth`：L=32 + AttnRes Full ON 下 grad_ckpt 代价 1.116×、
省 4.1× 峰值内存；`eff.depth_shape_matched_pair`）**全都是 ON 那一臂的**。
**OFF 臂在任何深度上都没有配对读数**，所以现在无法回答"AttnRes 值不值"。
**这个空白是三问里唯一"一个 run 就填满"的**——这是它进入四个 run 的理由，
也是（1）被延后的对照：（1）问的方向今天没有任何读数指向它。

**预注册读数**：0.02 nat 门（见 §4 的 sigma 说明）+ 吞吐差。**AttnRes OFF 必然更快**（少一路深度注意力），
所以读的是**它换来多少 loss**，不是"哪个快"。

**两种结果各触发什么**：
- **OFF 的 loss 劣化 < 阈值** → **关掉**，把省下的吞吐写进 200M/300M 配置，
  并撤掉 `Block.sublayers()` 的必要性（**但 b0-8 的 `AttnRes` 构造期守卫保留**——
  它防的是"配置说开了实际没开"，与开关本身正交）。
- **OFF 的 loss 劣化 ≥ 阈值** → 保持 ON，**把这个配对读数落成 fact**，
  它是 AttnRes 第一次有 OFF 臂对照。

## 3. ~~R3-lr：按块类分 lr~~ —— **已撤（fb 裁定 2026-09-02，见 §6）**

**撤的理由不是"1.63× 太小"，是"1.63× 也是单对读数、且落在 warmup 后第一个窗口"**——
用它反推 0.61 会重复 0.28 的同一个错误：**拿一个未稳定的比值当一个常数**。
**b0-12 保留三个 run（B0、B0-seed2、R2-off），第四个 slot 空着**，
等 p200m 续训后第二个区间给出稳定的 KDA/MLA 比，再决定第四问是 lr 还是别的。

**§3 原有的 val-loss 读法保留给 R2**（fb 明确：不给 R3）。下面整节留作历史与推导记录。

### 原 R3-lr 的形状与两次系数作废（历史）

**fb 裁定的形状**：A 臂 = 现状（**无残差输出缩放、Muon 单一 base lr**），
B 臂**只改一件事**：KDA 块的 lr 乘一个 <1 的系数。
**残差缩放 (3b) 不做**——两臂同时改无法归因。

**b0-9 的第三问是什么、为什么作废**：它问"`1/sqrt(L) = 0.61` 在 Muon 下对不对"。
**那个 0.61 不是 `1/sqrt(L)`**——它是 experiments 第 171 行的 `--lr_scale 0.61`，
一个 ledger 旋钮；`1/sqrt(32) = 0.177`。**一个把旋钮值当成理论规则的问题，
两种结果都读不出东西**，所以整问撤掉。**3a 的输入换成实测量**（3.4–3.7× 增长比），
这是它和 b0-9 第三问的根本区别。

### 0.28 这个系数已经作废，原因是第三个区间（step3000 读数，2026-09-02 11:0xZ）

**先给三个区间的全貌**，把"范数增长超出 1.0 的部分"当作与 lr 一阶成正比，
等化系数 = MLA 超出量 / KDA 超出量：

| 区间 | KDA−1 | MLA−1 | 比 | 反推系数 |
|---|---|---|---|---|
| 1500→2000 | 0.088239 | 0.023570 | 3.74× | 0.267 |
| 2000→2500 | 0.040859 | 0.011895 | 3.43× | 0.291 |
| **2500→3000** | **0.049344** | **0.006199** | **7.96×** | **0.126** |

**0.28 是前两个区间的均值（3.589 → 0.279）。第三个区间是 7.96×，系数 0.126——
差一倍多。** 这不是噪声，两条分量各自都是单调的：

- **MLA 增长每个区间对折**：0.0236 → 0.0119 → 0.0062。
- **KDA 增长掉头往上**：0.0882 → 0.0409 → **0.0493**。

**所以 7.96× 主要是 MLA 减速更快造成的，不是 KDA 加速跑掉。**
**含义是致命的：这个比值不是一个稳定属性，它随训练进程漂移，所以"把它等化到 1"
没有一个固定的靶。** 用任何单一区间反推的系数，都只对那个区间成立。

**R3-lr 因此必须改，改法有两条，都要 fb 裁：**

1. **把靶从"比值"换成"比值的斜率"**：读数改为"分 lr 后，比值随 step 的漂移是否变平"，
   而不是"比值是否落在 [0.8, 1.25]"。**代价是这需要至少三个 checkpoint，1B/954 步
   在 `--save_every 500` 下只有两个**（step500、954 收尾），**所以要改成
   `--save_every 250`**——不加卡时，只多写几个 2.1GB 文件。
2. **或者放弃等化，改问一个有固定靶的问题**：B 臂 KDA lr × 0.28，
   **读数只留 val loss**（不劣于 A 臂即算"KDA 块可以用更低 lr 而不损失质量"）。
   **这一条今天就可读，且不依赖任何线性假设。**

**我的判断：选 2。** 第 1 条要求"漂移变平"，而**漂移本身的成因还没查清**
（MLA 对折 + KDA 反转是两个独立现象），**在成因未知时把它当优化目标，
就是 §3 末尾那条"范数增长比不是可优化的目标"的负结果提前发生**。
选 2 只花一个 run，答一个确定能答的问题。

**原先记录的两层风险仍然有效，且第三个区间证实了第二层**：
（a）线性假设未验证——Muon 把更新正交化，更新范数主要由 lr 和形状决定而非梯度大小，
**所以线性假设在 Muon 下比在 AdamW 下更可能成立，但这是推理不是实测**；
（b）**3.589 是 500M/L32/24KDA+8MLA 上读的，臂跑在 200M/L12/9KDA+3MLA 上**——
现在连同一个 run 内部、相邻两个区间都能从 3.43 跳到 7.96，
**跨规模不变的假设更没有依据了。**

**预注册读数——按上面的判断，只留第 2 条为硬判据**：
1. ~~**KDA/MLA 范数增长比收敛到 ~1**（判据：落在 **[0.8, 1.25]**）~~
   **作废**：靶不固定（同一 run 内 3.43 → 7.96）。**比值仍然记录并逐区间打印**，
   但它是观察量不是判据。
2. **val loss 不劣于 A 臂**（差 < 0.02 nat 门）——**唯一的胜负判据**。
   **读的是"KDA 块用更低 lr 会不会掉质量"，这个问题有固定靶、不依赖线性假设。**

**第 1 条在 L=12 上的统计基础弱得多，而失效方式和我上一版写的不是同一个**：
`ckpt_health.py` 的 MLA 中位数在 L=32 上取自 **8 层**，在 L=12 上只有 **3 层**。
**上一版写"一层异常就能把整组挪走"——实测这是错的**，跑 `robust_z` 验了：

```
n=3，一层跑飞 (1.01, 1.02, 1.60):  z = [-0.7, 0.0, 39.1]  → 抓到
n=3，两层散开 (1.01, 1.20, 1.50):  z = [-0.67, 0.0, 1.06] → 漏掉
```

**单个离群点在 n=3 上抓得很好**（中位数和 MAD 都由另两层定，离群点动不了它们）。
**真正的盲区是"两层一起散开"**：三个点里有两个偏离，中位数就落在偏离的那一侧，
**MAD 变成偏离量本身**，于是 z 全部塌到 1 附近，没有一层过 3σ。
n=8 下同样的两层散开是 max z 3300（六个正常层把 sigma 钉住），**n=3 下是 1.06**。

**所以预注册的这一条不是"区间偏乐观"，是"3σ 判据在 n=3 上对某一类形状完全失灵"。**
**R3-lr 判定时必须打印三个 MLA 层各自的比值，不能只看中位数或 flag 数**——
**零 flag 在 n=3 上不构成"没有异常"的证据**。判据改为：
**三层比值的极差超过 25% 就按"增长比没收敛"处理**，不管有没有 flag。

**两种结果各触发什么**：
- **val loss 不劣（差 < 0.02 nat）** → **KDA 块可以吃 0.28 倍 lr 而不损失质量**，
  这本身就是可写进 recipe 的一条，300M 采用；**并把比值的三区间漂移落成 fact**
  （现在只有 b0-10 的读数，没有进 facts）。
- **val loss 变劣 ≥ 阈值** → 不采用，**并且"范数增长比是个该被等化的量"这个前提被否掉**——
  那是有价值的负结果，它省掉后续所有基于这个比值的调参。
- **比值在 B 臂下仍然漂移**（预期会）→ **不算失败**，因为它已不是判据；
  记录漂移形状，留给"成因是什么"这个单独的问题。

## 4. R1：KDA:MLA 比例 —— **已预注册，延后，不占这四个 run**

**为什么延后（fb 裁定，理由是空白硬度不是重要性）**：§2 的 OFF 臂在任何深度都没有
配对读数，§3 有 3.4–3.7× 的实测动机，**（1）两者都没有**——现状 3:1 已有 20B token
的运行记录，而"更稀疏会不会更好"今天只是猜想，没有任何读数指向它。
**下面整节保持可跑状态**，等 R2/R3 的结论回来再排。

**问的数**：val loss（同 mix、同 token、同 seed）。
**A 臂 = 现状 3:1** = B0（3 MLA + 9 KDA，MLA 在 2/6/10）。
**B 臂 = 5:1**（2 MLA + 10 KDA）——**比现状稀疏一档，L=12 上唯一的整数选项**。
**C 臂 = 1:1**（6 MLA + 6 KDA，交替）。

**三个点而不是两个**：5:1 和 1:1 在现状两侧各一档，
**三个点能区分"单调"和"3:1 已是内点最优"，两个点不能**。
**所以将来重启这一问时，只加 B 臂是半个实验**——它答不出 3:1 是不是内点最优。

**sigma 复用有条件**：B0/B0-seed2 定出的 sigma 是 **L12 + AttnRes ON + 单一 base lr**
下的。**若 R2 判 OFF 胜、或 R3 判分 lr 胜，基线配置就变了，这一问要重新定 sigma**——
届时 R1 的成本是 2 个 run（新基线 + 新 seed）加 2 个臂，不是 2 个臂。

**两种结果各触发什么（保持预注册状态）**：
- **5:1 优于 3:1 ≥ 阈值** → p300m 用同比例（**按 L=18 重排 MLA 位置和个数，
  不照抄 4/18**，见 §1 三），且 R3 的 lr 系数按新的 KDA 块数重算。
- **5:1 不优，或 1:1 优于 3:1** → 保持 3:1，**把"MLA 密度不是当前瓶颈"写进 facts**。
- **三臂都在阈值内** → 比例不敏感，**取最省的**（KDA 每块参数更多，则 1:1 更省），
  理由记进 fact。

## 4.5 open 项（不改代码，只记事实）

- **`safe_gate` 的 `lower_bound=-5.0` 同时限住两端**（`fla/ops/kda/gate.py:69`），
  所以每 token 衰减恒在 `[exp(-5), 1] = [0.0067, 1]`。**不存在"衰减无界"的风险。**
  存在的风险是**门饱和**：`exp(A_log)` 大到 66 时非饱和区只有 0.08 宽，门退化成阶跃。
  **这一条按 fb 裁定进 open 项，不改代码**——`lower_bound` 的值是 fla 的默认，
  改它等于改架构，而现在没有任何读数说 −5.0 是错的。
- **NoPE 下位置信息全在 KDA 状态里**（fb 指出），所以衰减过快直接吃位置。
  **但按上一条，衰减有下界 0.0067**；真正要盯的是**饱和后能否还区分不同距离**。
  这需要 forward 一个真 batch 读 `g` 的分布，**CPU 可做，排在续训后第二个区间一起**。

## 5. 顺序与依赖

**四个 run 全部串行，排在 `p300m_6b_0902` 之后**，不与生产 run 抢卡。
**顺序是 B0 → B0-seed2 → R2-off → R3-lr**（R2 先于 R3，fb 同意 2026-09-02）。

1. **B0**：三问的共用基线。**它同时是 §3 那个 0.28 的前置**——
   落盘后先用 `scripts/ckpt_health.py` 在 L=12 上重读 KDA/MLA 增长比，
   **不在 3.0–4.2 之间就先改系数再跑 R3-lr**（见 §3 第二层风险）。
2. **B0-seed2**：定 sigma。**在它之前，任何"胜负"都读不出来**，
   所以这不是准备工作，而是让后两个 run 可读的必要条件。
3. **R2-off**：只依赖 sigma，不依赖 B0 的范数读数，**所以它排在 R3 之前**。
4. **R3-lr**：依赖 sigma 和 B0 的 L=12 增长比两者。

**R2 和 R3 之间没有依赖，但顺序仍不能换**：R2 若判 OFF 胜，
**基线定义就变了**（块少一路深度注意力，KDA/MLA 的范数占比要重读），
那时 R3 的 A 臂应当是 OFF 配置。**先跑 R2 使这个分支能被发现；先跑 R3 则发现不了**——
它会安静地对着一个可能被淘汰的基线出结论。

**这个顺序里没有 R1**：它延后（§4），且**将来重启时不能直接复用这批 sigma**，
理由在 §4。

- **【新增观察，500M 上没有】A_log 高端在 200M 上快速攀升。**
  KDA layer 1 的 A_log max **1.844 → 4.188**（332 步，`exp()` **6.3 → 65.9，10.4 倍**），
  而该层同时是两个 weight-norm flag 之一（ratio 1.348，z +3.17）。
  **500M 的 A_log max 在 step2500→3000 持平**（+1.4688 未变）。
  **均值下移（0.148 → −0.168）而最大值上移**：每头衰减率的分布在**散开**，不是平移。
  ~~`model.py:137` 只传 `lower_bound=-5.0`，**低端有夹、高端无界**。~~
  **这句错了，我读了 fla 源码后自己推翻的（2026-09-02）。**
  `fla/ops/kda/gate.py:69`（`safe_gate=True` 走的那条）是：

  ```python
  g = lower_bound * F.sigmoid(A_log.view(H, 1).exp() * g)
  ```

  **`-5.0` 是一个 sigmoid 的乘数，不是一个下夹**——所以 `g_out ∈ [-5, 0]`
  **对任何 A_log 都成立，两端都有界**。A_log = 4.19 还是 400，值域一样。
  **而且 `exp(A_log)` 根本不是衰减率**：它是 sigmoid 内部的斜率。
  我上一版报的"exp 6.3 → 65.9，衰减涨 10.4 倍"**把一个斜率读成了一个速率**。

  **A_log 变大真正做的事是让门饱和**：`exp(A_log)` 从 1.25 涨到 66，
  使门处于非饱和区的 `g` 区间宽度从 **2.00 塌到 0.08**（判据：0.05 < sigmoid < 0.95）。
  **门变成阶跃**——每 token 的衰减几乎只取 `exp(0) = 1`（全记）或 `exp(-5) = 0.0067`（全忘），
  中间没有。**所以这不是"记忆窗过短"的风险，是"门失去连续调节能力"的风险**，两者要查的东西不同。
  **混淆未排除**：step 500–832 是 warmup（300 步）之后的第一个窗口，
  而 500M 的读数在 step 2500 之后。**所以这是观察不是结论**，
  分辨"早期瞬态"与"持续发散"需要 200M 续训后的第二个区间。
  **按 fb 的判据（少数头 vs 整层中位）实测的结果：是分化，不是发散。**
  KDA layer 1 的八个头，step500 → step832：

  ```
  -0.16 → -0.47   +0.15 → -0.18   +0.16 → -0.12   +0.26 → -0.10
  +0.67 → +0.22   +0.67 → +0.42   +1.36 → +2.06   +1.84 → +4.19
  ```

  **六个头下移，两个头上冲；中位数 +0.670 → +0.220，是下移的。**
  fb 的判据是"整层中位上移才算发散"——**中位在降，所以按这条判据不是发散**。

  **但结合上面的饱和分析，判据要加一条**：那两个上冲的头
  （`exp(A_log)` = 7.85 和 66.0）**门已经饱和**，非饱和区宽度 0.08。
  **"分化"和"两个头的门坏掉"在 A_log 的中位数上长得一样**——
  下一次读要按头报非饱和区宽度，不只报中位数。
