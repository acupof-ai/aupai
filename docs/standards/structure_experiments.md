# 三个结构实验：在 200M 上各跑 1B token，不用 100M 这一级

**这页的规矩：一个 run 一个变量，读数在开跑前写死，两种结果各对应一个动作。**
没有"看情况再说"的分支——那等于没有预注册。

## 0. 基线事实（读出来的，不是推的）

从 `ckpt_p500m_20b_0902.pt.step2500` 读：

| 事实 | 值 | 怎么读到 |
|---|---|---|
| 块布局 | **32 块 = 24 KDA + 8 MLA，MLA 在 3/7/11/…/31** | `blocks.<i>.mixer.A_log` 在不在 |
| KDA 参数占比 | mixer 126.2M + ffn 226.5M = **352.7M（块参数的 67%）** | 2D 权重逐个求和 |
| 每块参数 | KDA 14.71M / MLA 13.38M（**近乎相等**） | 同上 |
| KDA/MLA 范数增长比 | **3.74×（step1500→2000）、3.43×（2000→2500）** | `scripts/ckpt_health.py` 按块类拆 |
| 张量范数中位 | **KDA 42.88 > MLA 33.77** | 同上 |
| FP8 覆盖 | 块内 linear **全覆盖**；只有 LM head 不走（6.38%，已判决 no-ship） | `_fp8_ok` 逐个核 |

**那个 3.4–3.7× 不是小分母造成的**：如果 KDA 权重更小，同样的绝对更新会显示成更大的相对增长。
**实测 KDA 范数更大（42.88 vs 33.77），每块参数量也几乎相等**，所以两个最可能的伪影方向都排除了。
KDA 块**又大又长得更快**，这是实验（3a）的动机。

## 1. 规模与预算：结构实验不该在 100M 上跑

**三个结论，都改变 b0-11 的形状，都需要 fb 裁：**

**一、100M 比 200M 更贵。** `facts/efficiency.json#eff.fb_mfu` 的 **73K tok/s/gpu**
（31% MFU、FP8、8×H20、batch 32、seq 4096、no grad_ckpt）量的正是
**206M / L12 / d1024**——**p200m_4b 的配置**。所以：

| 方案 | 卡时/run | 吞吐来源 |
|---|---|---|
| **200M @1B** | **3.8** | **实测**（`eff.fb_mfu`，同配置） |
| 100M @2B，73K | 7.6 | 外推 |
| 100M @2B，100K | 5.6 | 外推 |
| 100M @2B，150K | 3.7 | 外推 |

**100M 要便宜过 200M@1B，得跑到 150K tok/s/gpu——那是实测值的 2.05 倍，没有任何依据。**
**200M@1B 更便宜、吞吐已实测、而且它就是验收所在的那一级**，不需要"是否外推到 200M"这一跳。

**二、按这个价，三问全部装得下。**

| run | 问题 | 配置（L12 d1024，1B token） |
|---|---|---|
| **B0** | 共用基线 | 3 MLA + 9 KDA、AttnRes ON、单一 base lr |
| **B0-seed2** | 定 sigma | 同 B0 换 seed |
| R2-off | （2） | AttnRes OFF |
| R1-5to1 | （1） | 2 MLA + 10 KDA |
| R1-1to1 | （1） | 6 MLA + 6 KDA |
| R3-lr | （3a） | KDA 块 lr × 0.28 |

**6 run × 3.8 = 22.8 卡时 = p200m_4b 生产 run 的 1.5 倍。** 仍然贵，但不是我上一版的
3.0 倍，而且**买到的是三个问题的答案而不是一个**。**若 fb 坚持"至多三个 run"，
砍的顺序是 R1-1to1 → R3-lr → R1-5to1**，理由见 §2/§4 各自的空白硬度。

**三、`7:1` 在这个阶梯上不存在。** MLA 数必须是整数：

| L=12（p200m） | 可达比例 |
|---|---|
| 1 MLA + 11 KDA | 11:1 |
| **2 MLA + 10 KDA** | **5:1** |
| **3 MLA + 9 KDA** | **3:1（现状）** |
| 4 MLA + 8 KDA | 2:1 |
| **6 MLA + 6 KDA** | **1:1** |

**7:1 在 L=12 要 1.5 个 MLA，在 L=18 要 2.25 个。** 我上一版的 7:1 是从 500M 的
L=32（4 MLA = 7:1）抄来的——**把一个只在 L=32 成立的配置写成了阶梯的臂**。
**B 臂改为 5:1（2 MLA + 10 KDA）**，它是 L=12 上"比现状更稀疏一档"的唯一整数选项。

**顺带一个阶梯自身的不一致，值得 fb 知道**：`stop_window_2026-09-02.md` 的
p300m 是 **L18 / 4 MLA + 14 KDA = 3.5:1**，不是 3:1。
**所谓"现状 3:1"只在 p200m（L12）和 p500m（L32）上成立**，300M 已经偏了。
（1）如果在 200M 上定出一个比例，**300M 要按同一比例重排 MLA 位置，不是照抄 4/18。**

**我上一版的算术错在哪，值得记**：写的是
`2e9/(30e3×8) ≈ 8,333 卡秒 ≈ 2.3 卡时/run`。**8,333 是墙钟秒，不是卡秒**——
除以 8 之后再当卡时算，把成本低报 8 倍。同一个 30K 下真值是 18.5 卡时。
**错误不在 30K 这个外推上（那只差 2.4×），在单位上：一个"卡时"里的"卡"被约掉了。**
两个错叠起来报出 2.3 对着真实 7.6，低报 3.3 倍——**而正是这个低报让"六个 100M run"
看起来可以接受，掩盖了"100M 比 200M 贵"这个真正的结论。**

## 2. 实验（1）：KDA:MLA 比例

**问的数**：val loss（同 mix、同 token、同 seed）。
**A 臂 = 现状 3:1** = B0（3 MLA + 9 KDA，MLA 在 2/6/10）。
**B 臂 = 5:1**（2 MLA + 10 KDA）——**比现状稀疏一档，L=12 上唯一的整数选项**。
**C 臂 = 1:1**（6 MLA + 6 KDA，交替）。

**为什么是三个点而不是两个**：5:1 和 1:1 在现状两侧各一档，
**三个点能区分"单调"和"3:1 已是内点最优"，两个点不能**。
**这是 R1-1to1 优先于 R3-lr 被砍的唯一理由**——砍掉它，（1）就只剩一个方向。

**预注册读数**：val loss 差 **≥ 0.02 nat** 算可读（`ds.seed_variance_0p2b` 的 sigma-hat
0.0516，2.28 sigma = 0.1176 是 500M 的门；**200M/1B 的 sigma 未测，
B0 与 B0-seed2 定出它之前这一条读不了**）。

**验收（b0-11 明写）**：这些 run 就在 200M 这一级，**但它们只有 1B token，
生产 run 有 4B**。所以"在 200M 或 300M 上复现"仍是独立一步：
**1B 上的胜负要在 4B 生产 run 上同向，才写进 recipe。**

**两种结果各触发什么**：
- **5:1 优于 3:1 ≥ 阈值** → p300m 用同比例（**按 L=18 重排 MLA 位置，不照抄 4/18**），
  且（3a）的 lr 系数按新的 KDA 块数重算。
- **5:1 不优，或 1:1 优于 3:1** → 保持 3:1，**把"MLA 密度不是当前瓶颈"写进 facts**。
- **三臂都在阈值内** → 比例不敏感，**取最省的**（KDA 每块参数更多，则 1:1 更省），
  理由记进 fact。

## 3. 实验（2）：AttnRes 开关

**问的数**：val loss 与 tok/s/gpu 的配对。
**A 臂 = AttnRes ON（现状 Full）** = B0，**B 臂 = OFF** = R2-off。

**这是真实空白，不是重复测量**：`facts/efficiency.json` 里所有 AttnRes 读数
（`eff.grad_ckpt_inverts_with_depth`：L=32 + AttnRes Full ON 下 grad_ckpt 代价 1.116×、
省 4.1× 峰值内存；`eff.depth_shape_matched_pair`）**全都是 ON 那一臂的**。
**OFF 臂在任何深度上都没有配对读数**，所以现在无法回答"AttnRes 值不值"。
**这个空白是三问里唯一"一个 run 就填满"的**——所以 R2-off 最后才被砍。

**预注册读数**：同上 0.02 nat 门 + 吞吐差。**AttnRes OFF 必然更快**（少一路深度注意力），
所以读的是**它换来多少 loss**，不是"哪个快"。

**两种结果各触发什么**：
- **OFF 的 loss 劣化 < 阈值** → **关掉**，把省下的吞吐写进 200M/300M 配置，
  并撤掉 `Block.sublayers()` 的必要性（**但 b0-8 的 `AttnRes` 构造期守卫保留**——
  它防的是"配置说开了实际没开"，与开关本身正交）。
- **OFF 的 loss 劣化 ≥ 阈值** → 保持 ON，**把这个配对读数落成 fact**，
  它是 AttnRes 第一次有 OFF 臂对照。

## 4. 实验（3a）：按块类分 lr

**fb 裁定的形状**：A 臂 = 现状（**无残差输出缩放、Muon 单一 base lr**），
B 臂**只改一件事**：KDA 块的 lr 乘一个 <1 的系数。
**残差缩放 (3b) 不做**——两臂同时改无法归因。

**b0-9 的第三问是什么、为什么作废**：它问"`1/sqrt(L) = 0.61` 在 Muon 下对不对"。
**那个 0.61 不是 `1/sqrt(L)`**——它是 experiments 第 171 行的 `--lr_scale 0.61`，
一个 ledger 旋钮；`1/sqrt(32) = 0.177`。**一个把旋钮值当成理论规则的问题，
两种结果都读不出东西**，所以整问撤掉。**3a 的输入换成实测量**（3.4–3.7× 增长比），
这是它和 b0-9 第三问的根本区别。

**系数怎么反推，和它两层风险**：把"范数增长超出 1.0 的部分"当作与 lr 一阶成正比，
则等化系数 = MLA 超出量 / KDA 超出量：

```
step1500→2000:  KDA 0.088239  MLA 0.023570  比 3.744  →  系数 0.267
step2000→2500:  KDA 0.040859  MLA 0.011895  比 3.435  →  系数 0.291
两区间均值比 3.589                            →  系数 0.279
```

**预注册系数 0.28。** **它的假设是"增长一阶线性于 lr"，这一条没有验证过。**
Muon 把更新正交化，更新范数主要由 lr 和形状决定而非梯度大小，
**所以在 Muon 下线性假设比在 AdamW 下更可能成立**——但这是推理不是实测。
**如果 B 臂的增长比落在 [0.7, 1.4] 之外，先怀疑线性假设，不要直接调系数再跑第二轮**：
那会变成用 run 拟合一个未验证的模型。

**第二层风险：这个 3.589 是 500M/L32/24KDA+8MLA 上读的，臂跑在 200M/L12/9KDA+3MLA 上。**
**换了深度、换了 MLA 数、换了 token 预算，比值没有理由不变。**
所以 0.28 是**先验，不是标定值**：**B0 落盘后先在 L=12 上重读一次增长比，
若不在 3.0–4.2 之间，用新比值反推系数并把 0.28 划掉**，别拿 L=32 的数去调 L=12 的 lr。

**预注册读数（两个都要满足才算 B 臂胜）**：
1. **KDA/MLA 范数增长比收敛到 ~1**（判据：落在 **[0.8, 1.25]**，即两侧各 25%）
2. **val loss 不劣于 A 臂**（差 < 0.02 nat 门）

**第 1 条在 L=12 上的统计基础比在 L=32 上弱得多，这是个真问题**：
`ckpt_health.py` 的 MLA 中位数在 L=32 上取自 **8 层**，在 L=12 上只有 **3 层**。
**n=3 的中位数就是中间那一层**，MAD 是三个偏差的中位——**一层异常就能把整组挪走**。
所以 [0.8, 1.25] 这个区间宽度是按 n=8 的稳定性定的，**在 n=3 上它偏乐观**。
**预注册加一条：R3-lr 判定时同时打印三个 MLA 层各自的比值，不只打印中位数**——
若三层散布本身就超过 25%，第 1 条读不出来，按"增长比没收敛"处理。

**两种结果各触发什么**：
- **两条都满足** → 300M 生产 run 采用按块类分 lr，系数写进 recipe；
  **并把"单一 base lr 下 KDA 块过快"落成 fact**（现在只有现象，没有干预证据）。
- **增长比收敛但 loss 变劣** → **不采用**，并记录"范数增长比不是可优化的目标"——
  这会是一个有价值的负结果，因为它否掉的是本实验的整个前提。
- **增长比没收敛** → 线性假设不成立，**停下来重新推系数**，不做第二个 run。

## 5. 顺序与依赖

1. **B0 + B0-seed2 先跑**：它们既是三问的共用基线，又是 §2 的 0.02 nat 门唯一的来源。
   **sigma 没定之前，任何"胜负"判断都不成立**，所以这两个 run 不是准备工作而是第一个结果。
2. **（2）AttnRes 其次**：只有一个新臂、最省，且它的结论会改变（1）（3a）的基线
   （AttnRes 关掉后块的定义变了，KDA/MLA 的时间与范数占比都要重读，B0 也要重跑）。
3. **（1）比例第三**：它决定（3a）的 KDA 块数。
4. **（3a）分 lr 最后**：系数依赖最终的 KDA:MLA 比例。

**顺序不能反**：如果先跑（3a）再改比例，那个 0.28 就是对着一个不再存在的配置反推的。

## 6. 作废条件

- **块布局变化**：§0 的 3:1 和 MLA 位置来自 step2500；若 200M 配置换了布局，
  §2/§4 的臂全部重定义。
- **3.4–3.7× 不在 200M/L12 上复现**：实验（3a）的动机消失，系数无意义。
  **它是从 500M/L32 读出来的，L12 只有 3 个 MLA、样本少三倍**；
  **B0 落盘后先用 `scripts/ckpt_health.py` 核这一条**，再决定要不要跑 R3-lr。
- **73K 在 1B 的短 run 上不成立**：`eff.fb_mfu` 是稳态读数，1B = 954 步，
  warmup 300 步占 31%，**启动与 warmup 摊薄后的有效吞吐必然低于 73K**。
  **B0 落盘后用它的真实墙钟重算 §1 整张表**；若低于 36K，200M@1B 就不再比 100M@2B 便宜。
- **0.02 nat 门未定**：`sigma` 是 500M/0.2B 的读数，**200M/1B 的 seed 方差没测过**；
  B0 与 B0-seed2 出结果之前，所有"可读"判断都是暂定的。
- **200M/300M 阶梯变化**：§1 的验收标准挂在这个阶梯上，阶梯改则验收改。
- **fb 坚持 100M**：§1 的三条结论全部作废，回到 100M@2B，
  但那时必须先实测 100M 的 tok/s/gpu，**不能沿用任何外推值**。
- **fb 坚持三个 run 上限**：砍 R1-1to1 → R3-lr → R1-5to1，见 §1 二。
