# p1 classifier annotation spec

The classifier line (owner e1, acceptance in `p1_data_recipe.md`) needs teacher
labels. This file is the contract between e1 (labels' owner) and de (serve).

## Labels

One integer 0-5 per file, educational value for a student learning to code.
The notion is phi-1's ("educational value for a student whose goal is to learn
basic coding concepts"), not FineWeb-Edu's college-educated adult, so the keep
rate stays comparable to phi-1's ~17%.

| score | meaning |
|---|---|
| 0 | not code, unreadable, minified, binary blob |
| 1 | autogenerated, boilerplate, config, obfuscated |
| 2 | glue code, nothing to learn from it |
| 3 | real logic but domain-specific/opaque or poorly written |
| 4 | clean, self-contained, demonstrates a clear concept |
| 5 | textbook quality, teaches a transferable concept |

One label per FILE; the model sees the file head and the head represents the
file (see Truncation).

## Prompt

The served model is `qwen38-27b`, a BASE model with no chat template (de,
2026-09-09), so the annotation runs as a raw completion prefix, not a chat
request. The exact prompt:

```
Rate the educational value of the following code sample for a student learning to code. 0 not code/unreadable/minified; 1 autogenerated/boilerplate/config; 2 glue code, nothing to learn; 3 real logic but domain-specific or unclear; 4 clean and self-contained, demonstrates a clear concept; 5 textbook quality, teaches a transferable concept. Output only the digit.

Code:
{code}

Score:
```

The model completes after `Score:`. The rubric text and the output format are
the contract; the `Code:/Score:` framing exists because a base model needs a
completion target, not because the labels depend on it.

## Output contract

Greedy (temperature 0), `max_new_tokens=2`. Parse: strip, take the first
character if it is in 0-5; otherwise retry once; on second failure discard the
sample and count it. Discards are reported, never silently replaced.

The model is a reasoning model: requests MUST set `reasoning_effort: "none"`
(or the serve must close the think block in the prompt). With default thinking
the 2-token budget is consumed by thinking tokens and no digit is produced.
Verified on the pilot (de, 2026-09-09).

## Truncation

`{code}` = the first 350 characters of the file (imports, docstring,
signatures, first bodies). Head-only is deliberate: it is cheap and the head
separates most classes (minified/autogenerated/junk show immediately). Known
failure mode: a boilerplate head over an instructive body scores low. The
threshold ablation and the 50-high/50-low two-reader spot check
(`p1_data_recipe.md` acceptance) quantify this; if the spot check shows
systematic head/body disagreement, head+tail replaces head-only at the cost of
roughly doubling the code-token budget.

## Budget

100,000 samples (phi-1's number; enough for a held-out AUC split).

| component | tokens/sample |
|---|---|
| rubric + template | ~75 |
| code head (350 chars) | ~115 |
| output | 2 |
| **total** | **~190** |

100K x ~190 = ~19M tokens, inside the 0.02B budget with margin for retries.

## Input samples

4c's composition decision (2026-09-09): the p1 filtered code draws from three
domains, not all nine -- code_rp1t_dd09 (6.24B tokens), code_rp1t_b2v2_dd
(3.60B), code_dedup08 (~8.95B), ~18.8B total. The other five code domains are
upstream stages and are not fed. e1 draws 100K rows from the three,
proportional to token share (33,210 / 19,160 / 47,630), seed 42, reservoir per
domain, rows of `{id, text}` (id = domain + shard + doc index; text = the head
350 chars). de does not generate inputs. The sample represents the classifier's
future inference distribution by construction. If 3b's near-dedup lands before
the full run, the sample is re-drawn (dedup is 3b's line; labels on duplicates
are consistent but the inference distribution changes).

## Pilot gate

RAN 2026-09-09 (de, 5-card serve, ~2 min, 1000 samples from code_rp1t):
histogram 0=6.1% 1=73.8% 2=3.1% 3=15.5% 4=1.5% 5=0.0%; discards 0/1000; all
outputs clean single digits. Spread exists, so the gate passed and the rubric
gains NO anchored examples -- adding them now would make pilot and full-run
labels incomparable. The 73.8% at 1 is consistent with web-scraped code being
mostly boilerplate; the upper tail (score >= 3) is 17.0%, coincident with
phi-1's ~17% keep rate, and the threshold ablation pins the operating point.
Score 5 never fired; if it stays at zero in the full run it is a dead level
and collapses into 4 at threshold time, not before.

## Enlarged pilot (4c, 2026-09-09)

The 1K pilot's discriminative mass is the 26% non-1 tail; at candidate
threshold >=3 it holds ~170 samples, too few to pick the threshold region.
Before the full run, label a 5,000-sample enlarged pilot drawn from the same
three domains as the full run, proportional to token share (1,660 / 958 /
2,382): it is the first-N slice of the full 100K draw (seed 42), so pilot and
full stay comparable and nothing is re-drawn. At the pilot's >=3 rate (~17%)
the enlarged pilot holds ~850 positives, a keep-rate half-width of ~1.2pp,
enough to select the threshold region; the threshold itself is pinned on the
full 100K ablation (acceptance criterion), not on the pilot. The enlargement
is drawn from the three deduped domains rather than code_rp1t because the
deduped distribution may differ from the raw pilot domain's, and the threshold
estimate must match the inference distribution.
