# p1 classifier annotation spec

The classifier line (owner e1, acceptance in `p1_data_recipe.md`) needs teacher
labels. This file is the contract between e1 (labels' owner) and de (serve).

## Labels

One integer 0-5 per file, educational value for a student learning to code.
The notion is phi-1's ("educational value for a student whose goal is to learn
basic coding concepts"), not FineWeb-Edu's college-educated adult, so the keep
rate stays comparable to phi-1's ~17%.

| score | meaning |
|---|---|
| 0 | not code, unreadable, minified, binary blob |
| 1 | autogenerated, boilerplate, config, obfuscated |
| 2 | glue code, nothing to learn from it |
| 3 | real logic but domain-specific/opaque or poorly written |
| 4 | clean, self-contained, demonstrates a clear concept |
| 5 | textbook quality, teaches a transferable concept |

One label per FILE; the model sees the file head and the head represents the
file (see Truncation).

## Prompt

System:

```
You are annotating code samples for an educational-value classifier. Rate how useful each sample is for a student learning to code. 0 not code/unreadable/minified; 1 autogenerated/boilerplate/config; 2 glue code, nothing to learn; 3 real logic but domain-specific or unclear; 4 clean and self-contained, demonstrates a clear concept; 5 textbook quality, teaches a transferable concept. Output only the digit.
```

User:

```
{code}
```

`{code}` is the truncated file text. The corpus records are
`{content, source, url}` with no language field; the rubric is
language-agnostic and the teacher infers the language from the code, so no
language hint is sent (code_rp1t is multilingual, so the classifier is
multilingual by construction). If the served model is a base model with no
chat template, the same text runs as a raw completion prefix (the contract is
the rubric text and the output format, not the wrapper).

## Output contract

Greedy (temperature 0), `max_new_tokens=2`. Parse: strip, take the first
character if it is in 0-5; otherwise retry once; on second failure discard the
sample and count it. Discards are reported, never silently replaced.

## Truncation

`{code}` = the first 350 characters of the file (imports, docstring,
signatures, first bodies). Head-only is deliberate: it is cheap and the head
separates most classes (minified/autogenerated/junk show immediately). Known
failure mode: a boilerplate head over an instructive body scores low. The
threshold ablation and the 50-high/50-low two-reader spot check
(`p1_data_recipe.md` acceptance) quantify this; if the spot check shows
systematic head/body disagreement, head+tail replaces head-only at the cost of
roughly doubling the code-token budget.

## Budget

100,000 samples (phi-1's number; enough for a held-out AUC split).

| component | tokens/sample |
|---|---|
| rubric + template | ~75 |
| code head (350 chars) | ~115 |
| output | 2 |
| **total** | **~190** |

100K x ~190 = ~19M tokens, inside the 0.02B budget with margin for retries.

## Input samples

e1 draws them from the code cache (`data/corpus/code_*`): uniform over files,
seed 42, 100K rows of `{id, text}` (id = domain + doc index; text = the head
350 chars). de does not generate inputs. The
sample represents the classifier's future inference distribution, so it comes
from the cache the classifier will filter. If 3b's near-dedup lands before the
full run, the sample is re-drawn from the deduped corpus (dedup is 3b's line;
labels on duplicates are consistent but the inference distribution changes).

## Pilot gate

Run 1,000 samples first and inspect the score histogram. If the teacher
collapses onto 3-4 (no spread at the tails), the 50/50 spot check has no
extremes to sample and the rubric gains one anchored example per level before
the full run. If the histogram has spread, the full run proceeds. The pilot is
the cheapest five hours of insurance this track has.
