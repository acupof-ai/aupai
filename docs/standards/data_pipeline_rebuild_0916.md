# Data funnel rebuild recipe after the 2026-09-16 pod loss

Scope: regenerating the **data funnel only** — gate tokenizer, decontaminated corpora,
NL KenLM, the stratified L2 pools, the locked κ sets, and teacher labels. Infrastructure
provisioning (container/hostPath mounts, claims, `~/bin/pod`, H20 assignment, persistent
backup) is a separate document owned by 66 and is a precondition assumed here, not described.

This is a recipe, not an executable plan: nothing here fetches or starts anything until a new
pod is provisioned and the user releases it. All code is on `main` (merge `0f5aa15e`,
PR #400; earlier #396). The destroyed emptyDir `/work/aupai` held no code and no irreplaceable
byte that is not regenerable by these steps from upstream corpora; the cost is re-fetch and
re-score, not recovery.

## 1. Gate tokenizer — recover the surviving local copy, do NOT retrain

The gate 32k tokenizer survived off-pod at `/Users/bytedance/code/aupai-de/data/tokenizer.json`
(verified 2026-09-16: 2,287,069 bytes, `<eos>=1`, `[NUM]=32767`, ids span the 32,768-slot
09-10 gate vocabulary — the 32,773-slot 0829 vocab, not this one). Copy it into the new
container's `data/tokenizer.json`, then run the final gates rather than rebuilding:

```bash
cp <laptop>/aupai-de/data/tokenizer.json data/tokenizer.json
python3 scripts/tokenizer_eval.py --tokenizers data/tokenizer.json --selftest
```
The gates must confirm round-trip lossless over all 256 bytes, hanzi whole-char ≥0.95, and
the pinned `<eos>=1` / `[NUM]=32767`. Retrain via `scripts/build_gate_tokenizer.py` only if
this copy fails those gates.

The chunk hard-max is measured **with this tokenizer** (decode→re-encode drifts +0..4 at cut
points), so the pool must be rebuilt against this exact vocabulary — the one the encoder
trains on.

## 2. Corpora — fetch → build (raw→corpus) → decontaminate

Three stages; the middle one was missing from earlier revisions of this recipe. Skipping it
leaves `data/corpus/<domain>/` empty so the filter glob matches nothing. All commands use the
mirror chain hf-mirror→modelscope→HF with `curl -4` (per `CLAUDE.md` pod rules).

**2a. Fetch raw** into `data/raw/<source>/` (`datagen/fetch_corpus.py --source <name>`;
`--source` is required). Named-source → rebuild-domain mapping:

| corpus domain | raw `--source` name | manifest fn in fetch_corpus.py |
|---|---|---|
| `en_c4_stage2` | `rp1t_c4` | `_manifest_rp1t_c4` (RedPajama-1T c4) |
| `code_py_starcoder` | `ms_starcoder_py` | `_manifest_ms_starcoder_py` (ModelScope python split) |

```bash
python3 datagen/fetch_corpus.py --source rp1t_c4         # -> data/raw/rp1t_c4/
python3 datagen/fetch_corpus.py --source ms_starcoder_py # -> data/raw/ms_starcoder_py/
# add --target_bytes / --stream_n --stream_i to cap size or shard across workers
```

**2b. Build raw → `data/corpus/<domain>/`** with `datagen/build_corpus.py` (NOT
`clean_corpus.py`: its `DOMAIN_SOURCE` maps only web_hq/cci3/en/code_rp1t and does **not**
cover either rebuild domain — that is expected, build_corpus is the path here). The en cell is
a domain-suffix rebuild, so `--phase` is REQUIRED to freeze the held-out slice; the recorded
lost-run shape was:

```bash
python3 datagen/build_corpus.py --domain en_c4 \
    --out data/corpus/en_c4_stage2 --phase <this-rebuild-phase> \
    --source 'jsonl:data/raw/rp1t_c4/*.jsonl' \
    --filters light --no_near_dedup --global-only --workers <N>
python3 datagen/build_corpus.py --domain code_py_starcoder \
    --out data/corpus/code_py_starcoder --phase <this-rebuild-phase> \
    --source 'jsonl:data/raw/ms_starcoder_py/*.jsonl' \
    --filters light --workers <N>
```

`<this-rebuild-phase>` and `--workers`/`--target_tokens` are operator-decided per the new
hardware; pin them in the run's experiment row. `--filters` has only two tiers (`web`, the
default, and `light`); `web`'s `not_zh` (>=60% CJK) would delete a code corpus and build_corpus
REFUSEs `code_py_starcoder+web`, so `--filters light` is required (confirm with `--dry` first).

**2c. Restore the 13-gram holdout bases, then decontaminate.**
`scripts/filter_gate_domains.py` exits immediately unless these are present (it does NOT
create them in production — the writes at filter_gate_domains.py:205-208 are `--selftest`
temp fixtures only). Both are `[EXTERNAL-FETCH]`, non-git, and were not on any surviving
local worktree (checked 2026-09-17): restore the EXACT canonical bytes before filtering,
because the 13-gram decontam identity depends on them.

- `data/eval/humaneval/humaneval_164.jsonl` — canonical 164-task HumanEval set (the same
  file `eval/humaneval_gen.py` reads as DATA_PATH). Controlled source, byte-verify.
- `data/eval/mbpp/mbpp_holdouts.jsonl` — the r3 clean 338/427 subset. It is DERIVED, not a
  single download: take external `data/eval/sanitized-mbpp.json` (non-git) and filter to the
  tracked id list `runs/contam_r3_mbpp_union.json` (`r3_mbpp_clean`, 338 ids) per
  `eval/mbpp_gen.py:47-51`. The union list IS on `main`; the sanitized MBPP source is not.

Then decontaminate `en_c4_stage2` → `en_c4_stage2_dc` and `code_py_starcoder` →
`code_py_starcoder_dc`:

```bash
python3 scripts/filter_gate_domains.py \
    --domains en_c4_stage2,code_py_starcoder --root /work/aupai
# writes data/corpus/<domain>_dc/ ; clean shards hard-linked, hit shards rewritten
```

Verify each re-fetched/rebuilt shard against its recorded sha before trusting strata
downstream.

## 4. NL pool (CPU)

```bash
python3 datagen/l2_label_pool_build.py \
  --nl-glob 'data/corpus/en_c4_stage2_dc/*.jsonl' \
  --nl-model runs/l2label/nl_c4_kn.model.json \
  --tokenizer data/tokenizer.json \
  --out runs/l2label/pool_en_c4.jsonl --seed 20260916
```
On the lost full-corpus scan 3.89M docs scored at ~600 doc/s single-core (~108 min pass 1);
17 spread shards (~795k docs) reached the same terciles in ~20 min and is the cheaper default
unless exact full-population terciles are required — record in the manifest which.

Post-build gate (must all hold; read from the manifest + a real-BPE rescan):
- `chunks_over_1024_must_be_zero == 0` for every kind, independently re-confirmed by
  re-encoding every emitted chunk with the gate tokenizer.
- `n_chunks_written` near 35,000; PPL bands populated at the 33/67 terciles (descriptive, no cut).
- `dropped_fragments` (<128 tokens) and `short_chunks_kept_128_511` counted, non-silent.
- `sample_id == sha256(content)[:16]`; no duplicate `sample_id`.

## 6. Locked κ sets + labels (after teacher is serving)

Re-draw is deterministic; see `runs/locked_en_README.md`.
```bash
python3 datagen/l3_stratified_sample.py --doc-id content --only-bands s,m,l \
    --per-stratum 100 --seed 20260916 \
    --glob 'data/corpus/en_c4_stage2_dc/en_c4_000.jsonl' --out runs/locked_en/en_locked_300.jsonl
# en_handread60: ~60-row human-read subset. The draw command was not recorded on the lost run

# seed family, reducing the per-stratum count to land near 60, e.g. --per-stratum 20 over
# s,m,l = 60 candidates, then take the fixed hand-read subset. Pin the exact per-stratum count
# in the new en_handread60 README when drawn, so it is deterministic for the rebuild:
python3 datagen/l3_stratified_sample.py --doc-id content --only-bands s,m,l \
    --per-stratum 20 --seed 20260916 \
    --glob 'data/corpus/en_c4_stage2_dc/en_c4_000.jsonl' --out runs/locked_en/en_handread60.jsonl
```
Serve the A3B teacher (sglang; model id is the FULL served path, not a short alias), then:
```bash
python3 datagen/l3_label_pilot.py --pilot runs/locked_en/en_locked_300.jsonl \
    --out runs/locked_en/kappa300.labels.jsonl --backend openai \
    --url http://127.0.0.1:30000/v1 --model /data00/models/Qwen3.6-35B-A3B-FP8
```
κ gate the user set before any scale (on the lost run: s-band edu ≤1-grade disagreement,
factual binary agreement 93%): human-read κ60 first; do not scale until it passes.

## 7. 50k labels, multi-endpoint

`cat` the two pools, validate `sample_id` uniqueness (`sort -u`), then:
```bash
python3 datagen/l3_label_drive.py --pool runs/l2label/pool_50k.jsonl \
    --out runs/l2label/labels_50k.jsonl \
    --urls 127.0.0.1:30000,127.0.0.1:30003,...,30007 \
    --model /data00/models/Qwen3.6-35B-A3B-FP8 --concurrency <benchmarked> \
    --ledger runs/l2label/l2_rubric_ledger.jsonl
```
- Benchmark `--limit 100..1800` first; six cards are NOT additive (measured 9.9 doc/s per
  isolated card, ~6.4 with CPU contention, 38.5 aggregate during a CPU build). Pick
  concurrency from the measured aggregate, target ≥50 doc/s with no CPU build running.
- Ledger is durable per row (ledger fsync before out; startup join reconciliation), so a
  crash resumes with out==ledger, no dropped/duplicate teacher calls.
- Report total, JSON success, per-endpoint throughput, 4-dim distributions, per-domain counts.
