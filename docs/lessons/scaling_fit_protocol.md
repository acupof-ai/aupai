# Scaling fit protocol (E + B/D^β), pre-registered

定稿于六个预算点重跑之前。拟合方式事后挑 = 指标事后挑的孪生问题,所以这份协议和评估面板同规则:
**第一个点跑完之后不许改,只许发新版并说明。**

**版本**:v1.9(2026-08-30)——D 必须取自 run 日志的 `tokens scheduled` 行(§1 修订);新增 D 偏差容忍度与曲线边界规则。v1.8 同日。

形式:L(D) = E + B/D^β,N 固定(~200M),D = 该点实际调度的训练 token 数。
六个点 D = 0.2 / 0.3 / 0.4 / 0.8 / 1.6 / 3.24B(×16.2 跨度,五点 ×2 几何级数)。
三参数六点 → 残差自由度 3,残差的**符号模式**比大小更有信息(§4)。

## 1. 每个点读哪个数(钉死)

- **聚合 val NLL**:固定 val 集上的平均负对数似然,**最终 checkpoint**(不是 best-step——best-step 是选择,引入事后偏差;Chinchilla 用训练 loss 是因为他们假设无限数据,我们有 val 就用 val)。
- **val 集 = 每个域 shuffle 后的前 5000 行**(train.py 的 `val_rows_max=5000` 已实现),七点共用同一份。域内 shuffle 是 §6 的硬性前置条件。
- 同一个语料快照(指纹钉死,3b 重建落地后快照,六点全部在它上面训)、同一个 tokenizer/vocab、bf16 权重、确定性 eval(无采样)。
- **不用**训练 loss、不用分域 NLL 做主拟合。分域 NLL(面板指标 1)作为二级报告,不进主拟合。
- D = 实际调度 token 数(**v1.9 修订:必须取自该 run 日志的 `mix: <n> rows = <x>B tokens scheduled` 行,
  train.py:1384;不按 mix json 的 total_tokens**)。mix json 是预算,不是供给:
  精确行数实测(harness.py run pretokenize,fb 2026-08-30)总供给 3.6285B,
  冻结权重下 3.24b 点的需求六域落到行、web_hq 补余量——**真正的缺口在 val 切分**:
  train.py:1348 在 pool 存在之前先切 n_val(`seqs[n_val:]`),1362 的 epoch cap
  按 `len(pool)` 量,六个域各被自己的 n_val 封顶(textbook 20.49M / wiki 12.29M /
  en 8.04M / math 4.08M / code 2.88M / chat 1.91M,合计 49.7M = 预算的 **1.53%**),
  web_hq 的 +383.6M 余量不重分。**只有 3.24b 点绑定**(五个小点已查,无 cap)——
  误差全部落在对 β 杠杆最大的点上,把它往左推 1.53%,而 mix 文件声称它在请求位置。
  每个点记录三个数:D_requested(mix json)、D_scheduled(日志)、gap,并排可见。
  确认凭证:首个 3.24b run 的 `wants N rows, epoch cap leaves M -> capped` 行
  (1.53% 是代码路径+行数的预测值,非观测值;fact mlm.mix.val_split_caps_the_largest_point)。

## 2. 拟合方法(照搬 Chinchilla,一处不改)

Chinchilla(arXiv 2203.15556,Appendix A)的配方,直接照搬,因为 loss 尺度相同(他们 1.69–3,我们 1.66–1.99):

- **空间**:线性 (D, L) 空间。E 是加性渐近项,形式本身决定了不能 log 变换后再拟。
- **损失**:Huber,**δ = 10⁻³**(Chinchilla 原值)。这个 δ 让 >0.001 nat 的残差进入 L1 区——六点里一个坏点就能毁掉 OLS,Huber 把它的影响按线性而不是平方压住。
- **优化器**:L-BFGS-B(scipy),多起点网格取最优。网格按我们的参数域裁剪:β ∈ {0, 0.25, …, 1.5}(7),E ∈ {1.5, 1.6, …, 2.0}(6),B ∈ {100, 300, 1000, 3000, 10000, 30000}(D 用原始 token,~0.3 nat 跨度对应 B~10³–10⁴)= 252 起点。
- **不做**高斯平滑:平滑是 Chinchilla  Approach 1 对训练曲线的处理,我们读的是最终 checkpoint 的 val loss,每点一个数,无曲线可平滑。
- β 的 95% 置信区间:profile likelihood(Huber 目标值 Δ = 3.84)。六点三参数下区间必然宽,宽度本身要报。

## 3. 拟合优度判据(写死数值)

噪声锚点:val 测量噪声 ≈ 0.005–0.01 nat(35000 个 4096-token 块,σ_block≈1 → SE≈0.005);
run-to-run 噪声 ≈ 0.05 nat(Kaplan,ds.kaplan_noise;我们内部无重复 run,这是最弱的锚点——
拟合残差本身会反过来校准它)。

| 判定 | 条件 | 动作 |
|---|---|---|
| **ACCEPT** | RMS 残差 ≤ 0.05 nat 且 max\|resid\| ≤ 0.10 | 报 E / B / β + profile 区间,可用于插值 |
| **WEAK** | 0.05 < RMS ≤ 0.10 | 只作描述性报告,禁止外推 |
| **FAIL** | RMS > 0.10 | 幂律在该跨度不被支持,不报 E/B/β |

**v1.5 替换:上表的固定门槛在 σ̂ 实测后由 §9 的 σ 条件规则取代**
(ACCEPT 门槛 = 1.14σ̂,WEAK 上限 = 2.28σ̂)。σ̂ 出来之前仍按本表,
σ̂ 出来之后直接查 §9,不做新判断。

**df=3 边界(v1.5)**:6 点 3 参数,残差自由度只有 3。RMS 自身的相对不确定度
≈ 1/√(2·3) = ±40%——单次 RMS=0.05 的 95% CI 约 [0.03, 0.10],ACCEPT/WEAK 的
固定边界落在单次读数的 CI 内。**RMS 只配粗筛;§4 的符号形态(p=3.1%,不依赖 σ)
和 profile 区间是主判据。** 任何"RMS 刚好过线"的 ACCEPT 必须连同这条不确定性一起报。

β 的附加判据:profile 95% 区间必须落在 (0, 1.5) 内才算"对 β 有信息";区间跨 0 = 数据看不出改善,
区间顶到 1.5 = 饱和不在观测范围内,两种都只报区间不报点值。

## 4. 什么残差形态推翻幂律形式本身

残差符号序列(按 D 排序,六点):

1. **U / 倒 U 形**:符号恰为 `++--++` 或 `--++--`(两端同号、中间两点反号),
   且两端点 \|resid\| > δ_noise(=0.05,见 §3 噪声锚;**不是 §2 的 Huber δ=1e-3**——
   v1.3 澄清:1e-3 会让该条件几乎恒真,退化为只看符号)。幂律单调且导数单调,系统性 U 形说明真实曲线有幂律没有的曲率
   (双 regime、或地板效应)。随机符号下 p = 2/64 = 3.1%。
2. **单调漂移**:连续 ≥4 个同号残差(p = 16/64 = 25%,v1.3 修正:v1.2 写的 22/64=34%
   不可复现——6 位符号串含 ≥4 连同号的精确计数是 16,单独太弱)且该游程内每个
   \|resid\| > 0.01——形式在整个量程上系统性偏。
3. **LOO β 不稳定**:逐点剔除重拟,任一剔除使 \|β_full − β_loo\| > 0.15 →
   拟合被单点主导,报 "beta_unstable",β 点值不可信(以 profile 区间为准)。
   注意:这是**精度标志,不是形式否证**——RMS 可以很小而 β 仍然定不准,
   两者不互相替代。
4. **端点同号失效**:两个端点 \|resid\| > δ_noise(=0.05)且同号 → 曲线够不到数据的量程,形式失败。

任一条命中 = 形式被否证,**不允许通过调 δ / 换起点 / 丢点来救**(§5)。

## 5. 单点失败怎么办(现在定,不等它发生)

- **run 失败**(崩溃 / NaN / 没跑到预算):同配置重跑一次。再失败 → 升级给 fb,不许静默丢点。
- **跑出来了但是离群点**(\|resid\| > 0.10):**先查根因**(run 日志、mix、checkpoint 完整性、
  语料快照是否一致)。查到根因 → 修复重跑。查不到 → 点**留在拟合里**(Huber 已自动降权),
  拟合标注 "contaminated, n−1 effective"。**绝不因为拟合不好而丢点。**
- **端点(0.2b 或 3.24b)重跑后仍无效** → 整条曲线作废(外推锚点没了),书面报告原因。
- **内点重跑后仍无效** → 用 5 点拟,报 n=5 和缺口位置。

## 6. fb 的假设:六个点的有效配方是否相同

**跨域:否证(构造上)。** 六个 mix 文件的域权重逐位相同(实测:
web_hq 0.3238 / textbook 0.4962 / wiki 0.0757 / en 0.0495 / math 0.0252 / code 0.0177 / chat 0.0118,
每个点都一样);训练调度按 phase 把各域部分拼起来后 `randperm`(train.py:1328),顺序是交错的。
"小预算点只用了 web_hq 的一小部分"是对的,但**域间比例不随预算变**。

**域内:否证(v1.1 更正)。** v1.0 担心"行池按分片 glob 序取确定性前缀、小预算点吃域的头部"——
这个前提在当前代码里不成立:train.py:1129 在分词缓存构建时
`random.Random(Cfg.seed).shuffle(texts)`(seed=42 写进 Cfg、经 `vars(cfg)` 进 checkpoint;
2c7ccf4,8-26),**在 val 切分之前**;洗牌后的顺序随缓存持久化,六点共用同一缓存
(同一语料快照 + 同一 vocab)→ 每个预算点吃的是洗牌池的**随机前缀**,成分在期望上恒定。
v1.0 的错误是审计了语料构建层(build_corpus.py 确实不洗牌)而没审训练的分词缓存层;
pod 上的 train.py 落后 HEAD 142 个文件,没有任何东西会提示这一点(de 已上线 `pod_drift` 守卫)。
**教训:审计之前先确认审计对象的版本,且要审全链路。**

**前置条件(六点开跑前执行,de/3b 的领地,这里只写要求)**:
1. ~~域内洗牌~~ **已存在**(train.py:1129,见上)。六点必须共用同一分词缓存
   (= 同一语料快照 + 同一 vocab_id),缓存指纹不一致就重建,不许各点各建。
2. 语料快照冻结,六点共用,指纹进 PROVENANCE。
3. **warmup 固定 20 步,六点相同,不按比例**(v1.2 裁决,见 changelog)。
   实测(0.2b 点 218 步,同 seed 同数据):warmup=2 终 val 3.658,warmup=20 终 val 3.135,
   差 0.52 且每个记录步都输——纯 1% 没炸但满 LR 走早了、方向坏了、终点没追回来。
   **残留混杂(读 β 时必须带着)**:固定 20 步下 warmup 占比从 0.2b 的 9.2% 到 3.24b 的 0.57%,
   小点花更大比例在低 LR → 小点 loss 系统性偏高 → **β 被高估**。选了较小的偏差不等于没有偏差:
   两种方案偏差同向(都高估 β),固定比例那个实测更大(0.52),所以选固定步数。

洗牌后(已存在)每个预算点的前缀是域内均匀随机子样本,成分在期望上恒定,D 是唯一系统变量。

## 解读警告(读 β 必读)

固定 20 步 warmup 留下一个**已测量、未消除**的混杂:warmup 占比 9.2%(0.2b)→ 0.57%(3.24b),
小点 loss 系统性偏高,**β 被高估**。报 β 时必须连同这句一起报;点值和 profile 区间都偏。
若未来重跑六点用了别的 warmup 方案,本节作废重写——它绑定的是 v1.2 的具体选择。

**方法论一句**:一个"消除混杂"的修正可能引入一个更大的同向偏差(v1.1 的纯 1% 就是)。
判断哪个方案偏差更小需要测量,不能靠推理——本协议的 warmup 条款是测出来的,不是推出来的。

**语料质量警告(v1.4)**:web_hq 本版跳过 top-40 质量切,六点跑在比原声明更脏的语料上。
E 是"这份语料的地板"不是"模型的天花板";R 对加性熵免疫,非加性弯平不可测;
β 对恒定噪声比例免疫。完整解读规则与 W/F 证伪链条:决策树 v1.3 §4 补充。

## 9. ACCEPT/WEAK 门槛是 σ 的函数(v1.5,σ̂ 实测前写死)

σ = 每点 seed 间噪声。44 排了 4 个 seed 在 0.2b 上跑同配置(3 df,同时是 e1 A/B
的一个臂和 44 的 F 臂,零额外成本)——σ̂ 会有实测值。**门槛在 σ̂ 出来之前写成函数,
出来之后直接查表,不做新判断。**

**推导**:6 点 3 参数,残差 df=3。零假设(形式为真、噪声 iid σ)下 E[RSS]=3σ²,
E[RMS]=σ√(3/6)=**0.71σ**;零假设 RMS 的 95 分位 = σ√(χ²₃,₀.₉₅/6) = σ√(7.815/6) = **1.14σ**。
原固定门槛 0.05 ≈ 1.14×0.044,本来就是"Kaplan σ 下的零假设 95 分位"——
σ 条件规则是把这个隐含关系显式化,不是改判据。

**冻结规则**:
- **ACCEPT**:RMS ≤ 1.14σ̂(拟合与零假设分布不可区分 → 插值误差 ≤ 噪声)。
- **WEAK**:1.14σ̂ < RMS ≤ 2.28σ̂(误设存在但 ≤ 2× 噪声尺度)。
- **FAIL**:RMS > 2.28σ̂(误设超过噪声,形式错了)。
- σ̂ ≤ 0.035 时期望 RMS ≤ 0.025,固定 0.05 门槛有 2× 余量,两规则一致,用哪个都行。
- σ̂ > 0.07 时期望 RMS > 0.05,**固定 0.05 门槛下一个完美拟合也只有约一半概率过门——
  此时固定门槛作废,只用本规则**;RMS 判定整体按 §3 的 df=3 边界降级为粗筛。
- **Huber 警告**:δ=1e-3 在 σ~0.05 下所有残差都在 L1 区,拟合实质是 L1 回归,
  1.14σ 的 χ² 推导是 L2 近似(同阶,常数略偏)。**观测 RMS 落在门槛 ±0.02 内时,
  用实际 fitter 做参数 bootstrap(从拟合曲线 + σ̂ 模拟 6 点、同网格重拟、1000 次)
  取 95 分位定夺**——这条 escape hatch 现在写死,不是现场发明。
- **σ̂ 的代表性(v1.6 更正方向)**:σ̂ 在 0.2b(最小点)测得;大点训练更充分、seed 方差通常更小,
  所以 σ̂ 对阶梯是**上界**——但上界在这个门槛里**不等于保守**:σ̂ 偏大 → 门槛偏松 →
  **该拒的拟合被接受(假 ACCEPT)**。非对称读法(预注册):
  - **ACCEPT 判定带 "noise-loose" 标签**:拟合与形式一致,但不能排除大点真实 σ 只有 σ̂ 一半、
    真实 verdict 应为 WEAK。插值可用,外推禁止(WEAK 语义)。
  - **FAIL 判定是硬的**:σ̂ 高估时真实门槛更紧,RMS 超了更松的门槛只会更差,不会更好。
  - 主判据在 σ 无关项:§4 符号形态(p=3.1%)和 profile 区间——ACCEPT/FAIL 都以它们为准。
  - **摘帽规则(预注册,零成本)**:ACCEPT 后,残差 RMS 是 σ_ladder 的隐含估计
    (形式对时 E[RMS]=0.71σ)。若 RMS < 0.71σ̂(0.2b),σ 随 D 下降被证实,
    noise-loose 标签摘除,ACCEPT 转硬。这是预注册的摘帽,不是事后调门槛。
  - **为什么不在 3.24b 加 seed 测 σ 的 D 依赖性**:2 seed → df=1,σ 的 CI ~70× 宽;
    3 seed → df=2,还有 8×——花 200–300 GPU 分钟买不可读的数。摘帽规则给同样的信息,免费。
    若某个 ACCEPT 判定成为决策树分支的依据且摘帽条件未触发,那时再测(条件性预注册)。
- e1 的 A/B 用同一个 σ̂ 算它的 MDE(attn_ab_read_protocol.md §1),一次测量喂两处。

## 10. 简繁混合:D 轴同质性与 E 标签门槛(v1.7,占比出来之前写死)

背景:web_hq 检出繁体文档(n=1,非证据;44 在遍历里加简繁计数器)。
繁体在简体为主的 BPE 下 fertility 更高(每单位信息更多 token)。

**取数路径(代码实证)**:train.py:1161 `random.Random(Cfg.seed).shuffle(texts)`
在分词缓存构建时域内打散(seed 固定、六点共享同一缓存),build_mix 每 phase 再
randperm(train.py:1356+)。每个预算点吃的是同一打散池的**随机前缀**——
简繁比例在六点之间是常数(期望意义),最小点(0.2b,~5 万文档量级)的抽样
SE < 0.2%。"顺序取 + 繁体分布不均 → c 随 D 变" 的情形被代码排除。

**推导(与恒定噪声比例同构)**:c 常数 → D'=c·D 只被 B 吸收,
**β、曲线形态、Δ_double、R 不受简繁比例影响**。受影响的只有 E 的绝对值
(混合语料的每-token 渐近)与外部比较。val 集 = 打散后每域前 5000 行,
与训练同分布(p_trad 的 SE ~0.7%),train/val 匹配,拟合内部一致。

**预注册门槛(挂贡献量上,不挂占比)**:
测两个数——p_trad(44 的计数器)和 ΔE_script(最强 checkpoint 上 val 集按
文字拆分的 per-script NLL 差;直接测量,不猜 fertility):

- **ΔE 双测(v1.8 修订,方向陷阱)**:繁体 fertility 更高 → 同样文本切得更碎 →
  **单 token 预测任务更容易,ΔE_token 可能为负**。per-token 和 per-char 两个都测:
  ΔE_char = E_trad_token·k_trad − E_simp_token·k_simp(k = 该 script 的 tok/char,
  实测 1.164×)。**符号规则(预注册):ΔE_token < 0 不得读成"繁体语料更好"——
  那是切得更碎的伪影;信息层的读法只看 ΔE_char。**
- **门槛用 |p_trad·ΔE_token|**(E 是 per-token 量,materiality 与方向无关):
  - **≤ 0.05 nat(噪声锚)**:不动作。对 E 的影响低于噪声,语料标签维持 v1.4 写法。
  - **0.05 < |贡献| ≤ 0.10**:E 的语料标签加简繁项(p_trad、ΔE_token、ΔE_char、
    对 E 的贡献量),作为 E 的不确定性上报;β/曲线结论不受影响。
  - **> 0.10**:混合实质移动 E。两个预注册动作:
    (a) fertility 校正 D:D' = D·(1−p+p/k),D 与 D' 两个拟合都报;
    (b) E 只报"混合语料地板",永不报"模型天花板"(v1.4 规则的强化)。
- ΔE 在新架构 3.24b 上测;六点跑完前若 p_trad 已大,旧架构 3.24b 可给临时值
  (架构影响 gap,标注临时)。
- **侦察先验(不进决策,44 全量为准)**:前 3 shard p_trad≈15.2%(篇级)/14.8%(字级),
  k≈1.164×(语料级;最小对 1.33–1.43×,n=2);若 |ΔE_token|≈0.3,贡献≈0.045,
  **可能正坐在门槛上**——侦察值来自前 3 shard,若语料按来源排序则有偏,全量以 44 为准。

**D 轴重复事实(v1.8 补)**:web_hq 全量 ≈1.434B token(62 shard 抽样);
3.24b 点按 32.4% 权重需 ~1.05B → **epoch 0.73,六个点里没有任何一个把 web_hq
重复一遍**,重复混杂在 D 轴上不存在。

## 11. D 偏差容忍度与曲线边界(v1.9,看到 3.24b 日志之前写死)

**推导(门槛的依据,先于测量)**:D 误差对拟合的杠杆 = 曲线斜率 × 相对误差。
最大点每倍增收益 Δ_double ≈ 0.059 nat(β≈0.5、R≈0.2 的量级),相对误差 ε 的
损失移动 ≈ 0.059·ε/ln2 ≈ 0.085ε nat。达到噪声地板 0.05 需要 ε ≈ 59%——
**D 误差要到 ~60% 才够格移动拟合**,y 噪声在很宽的范围内压过 x 误差。

**规则**:
- **|D_scheduled − D_requested| / D_requested ≤ 10%**:吸收为舍入。
  10% 的杠杆 < 0.01 nat(噪声的 1/5),且远在已知测量值(6.4%)之上。
  gap 仍逐点记录(§1),不静默。
- **> 10%**:宣布**曲线边界**——曲线的有效定义域到 D_scheduled 为止,
  禁止向请求预算方向外推;该点在拟合图上按 D_scheduled 画,误差棒标 gap。
  这是边界声明,不是舍入吸收。
- **mix 偏移条款(独立于 D 偏差)**:任何域的 epoch cap 使该域实际份额偏离
  声明权重 >1pt(总 mix 的 1%),无论 D 差多少都宣布——六点的 mix 恒定是
  §6 的前置条件,份额偏移是另一个维度的违规。当前已知:3.24b 点 wiki 若 cap,
  份额偏移 ~0.5pt,在条款内。

**v1.9.1 勘误(fb 2026-08-30 精确行数,同日)**:门槛选定后 fb 更正了供给事实——
wiki 不缺(早先 6.4% 缺口是采样 bytes/token 估计的误差,±2% 误差棒被用来做了
细于误差棒的断言);精确行数下六域需求落到行,真正的 cap 是 val 切分(§1 已改写)。
**预测 gap = 1.53%,在 10% 门槛内 → 吸收为舍入,逐点记 gap,不宣布边界。**
mix 偏移条款复核:六域各被 n_val 封顶后,份额偏移最大的是 web_hq(+0.51pt,
因总量缩水而相对上升),全部 <1pt,条款不触发。门槛本身在看到 1.53% 之前选定,
不受影响;1.53% 是预测值,确认凭证是首个 3.24b run 的 capped 行。
