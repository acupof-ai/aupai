Two of these are negative results, the class that vanishes when it is not written down; they are written down. The excursion closed on its own before the stop, with no intervention applied. ## 8. Throughput and MFU

Steady state from the pod log's clean intervals: 46K tok/s/gpu, 2.83 s/step, peak 44.1 GiB/card. The leg delivered 25,000 steps in 20.6 training-hours (11.1h for 13,500 steps to the stop, 9.5h for 11,500 after it), ~2.97 s/step including save/val dips.

The printed MFU (~278%) is not an efficiency and must not be quoted as one. `train.py:3792` computes `6 * n_dense * tps / peak`, and `n_dense` (train.py:3258) subtracts only memory-table params — all 48 routed experts count as if every token traversed them, so the number is arithmetically above 100% of the 148 TFLOPS bf16 peak. On active params (~0.2B) the same throughput is about 37% of peak. The fix is PR #40 (de-71, open; task de-71 in runs/tasks.jsonl): price active FLOPs, leave the dense arm's denominator alone.

The planning ratio stands: MoE-48 costs 1.263-1.283x the dense arm's step time at matched batch (facts/efficiency.json#eff.moe48_dense_step_cost_ratio), and the whole gap is overhead and shape, never extra arithmetic — active FLOPs are equal by construction ((top_k+shared)×expert_ffn = 4×768 = 3072 = ffn_hidden, facts/efficiency.json#eff.moe48_step_cost_breakdown).
