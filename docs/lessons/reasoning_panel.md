# 推理仪器栈(预注册,3.24b 落盘前)

目标变更:通用中文 LM → 推理模型(代码+数学,~30B token)。面板为"200M 上什么有分辨率"
而建,那个问题它答得好;但只有 math_v2_like 触及新目标,且它是**判别**任务
(在候选里选对答案),不是**推理**任务(产出推导)。GAP 仪器今天暴露的正是这个差:
同一份题,two-way 94.78、open-ended 30.90。**math_v2_like 94.69 是数学的 two-way;
数学的 open-ended 我们一个数都没有。**

## 1. 仪器栈(判别 → 产出桥 → 产出)

| 层 | 仪器 | 测什么 | 成本 | 现状 |
|---|---|---|---|---|
| L0 | math_v2_like | 判别(金答案 vs 扰动答案的似然) | 零 | 已有,在动(+11pt) |
| L0' | 代码判别(按执行通过率排序的似然) | 判别 | 数据集+脚本 | **缺口,需建** |
| L1 | few-shot 续写数学 | 产出(格式桥) | 零 GPU,换 prompt | **Q1 的判决实验** |
| L2 | 轻 SFT → pass@k | 产出(真仪器) | 一次 SFT run | L1 读数后定 |

**L1 是关键**:base 模型不主动解题——math-500 在 base 上 0/500 一半是格式问题
(base 续写文本,不回答问题),不全是能力缺失。few-shot 续写(给 2-3 个已解例题
再让模型续)桥接格式差,零 GPU。读法:最终答案精确匹配(boxed 或末位数字)。

**L2 是标准路径**:每个推理模型都走 SFT/RL。轻 SFT 教格式,pass@k 测能力。
SFT 后的 3.24b 若 pass@k 非零,项目可测;若仍零,200M 装不下推理产出,
需要 N 或别的路径——**这是项目可测性的判决,不是能力判决**。

## 2. Q1 的判决(3.24b 落盘后立即跑,预注册)

**在 3.24b checkpoint 上跑 L1(few-shot 续写数学,N≥500 题)**:
- **非零(>2δ,δ=1.4/√N≈6.3pt@500)**:仪器存在,产出半有信号。
  进入 L2 设计(SFT → pass@k 作为 30B 构建的转向量)。
- **零或 <2δ**:格式桥接不动,base 在 3.24b 仍不产出。
  进 L2(SFT 是唯一路径);L2 仍零 → **200M 规模上推理产出无仪器,
  这是本轮最重要的结论**——它改变项目可测性,先于可实现性。

**不跑的**:zero-shot 生成数学在 base 上(SKIP,格式+能力混淆,0/500 已证)。
SKIP 的是 zero-shot base,不是产出本身。

## 3. 可验证性不对称(fb 的 Q3,确认并写死)

数学/代码答案可执行验证——对就是对,错就是错,不需要裁判,不需要相似度。
这带来两个后果:

1. **标签无 MDE**:N 题精确匹配的误差是二项的 δ=1.4/√N(p=0.5 最坏情形),
   500 题 → 6.3pt,1000 题 → 4.4pt。没有 seed 方差进标签(执行是确定性的)。
   seed 方差仍在模型侧(不同 seed 不同模型),但单次测量的误差是二项的,
   比 NLL 的 σ̂=0.0516 锋利得多。
2. **A/B 更便宜**:推理数据配比的 A/B 用 pass@k,误差是二项+seed 方差,
   大概率比 NLL A/B 锋利。可验证标签移除了裁判/相似度问题(那是质量头沉没的原因)。

## 4. §8 形态迁不迁移(fb 的直接问题)

**形态逻辑迁移,具体指标不迁移。** §8 的四形态(A 容量/B 配比/C 齐动/D 不可读)
本质是"判别半饱和时产出半动不动"——这个逻辑与目标无关,推理版照用:
- pass@k 随 D 动、判别饱和 → 容量型;
- 判别动、pass@k 不动 → 配比型(或容量天花板);
- 都不动 → 不可读。

但 §8 的指标(lambada L2/O1/GAP)是表达能力的,不是推理的。**§8 不替换,
加兄弟**:推理版需要自己的产出半(L1/L2 的 pass@k)和判别半(math_v2_like +
代码判别),形态逻辑照抄。**当前阻塞:推理的产出半不存在(base 上 pass@k=0),
形态无法触发——L1 是前置条件。**

## 5. 代码侧的缺口

代码判别仪器(L0')不存在:需要一个带测试的代码题数据集(HumanEval/MBPP 类),
测模型是否给执行通过的完成更高似然。这是 3b/44 的数据活,不是我的读法活——
但**30B 构建要转向代码推理,这个仪器和 L1 数学一样是前置条件**,并列优先级。
