# 推理仪器栈(预注册,3.24b 落盘前)

目标变更:通用中文 LM → 推理模型(代码+数学,~30B token)。面板为"200M 上什么有分辨率"
而建,那个问题它答得好;但只有 math_v2_like 触及新目标,且它是**判别**任务
(在候选里选对答案),不是**推理**任务(产出推导)。GAP 仪器今天暴露的正是这个差:
同一份题,two-way 94.78、open-ended 30.90。**math_v2_like 94.69 是数学的 two-way;
数学的 open-ended 我们一个数都没有。**

## 1. 仪器栈(判别 → 产出桥 → 产出)

| 层 | 仪器 | 测什么 | 成本 | 现状 |
|---|---|---|---|---|
| L0 | math_v2_like | 判别(金答案 vs 扰动答案的似然) | 零 | 已有,在动(+11pt) |
| L0' | 代码判别(按执行通过率排序的似然) | 判别 | 数据集+脚本 | **缺口,需建** |
| L1 | few-shot 续写数学 | 产出(格式桥) | 零 GPU,换 prompt | **Q1 的判决实验** |
| L2 | 轻 SFT → pass@k | 产出(真仪器) | 一次 SFT run | L1 读数后定 |

**L1 是关键**:base 模型不主动解题——math-500 在 base 上 0/500 一半是格式问题
(base 续写文本,不回答问题),不全是能力缺失。few-shot 续写(给 2-3 个已解例题
再让模型续)桥接格式差,零 GPU。读法:最终答案精确匹配(boxed 或末位数字)。

**L2 是标准路径**:每个推理模型都走 SFT/RL。轻 SFT 教格式,pass@k 测能力。
SFT 后的 3.24b 若 pass@k 非零,项目可测;若仍零,200M 装不下推理产出,
需要 N 或别的路径——**这是项目可测性的判决,不是能力判决**。

## 2. Q1 的判决(3.24b 落盘后立即跑,预注册)

**在 3.24b checkpoint 上跑 L1(few-shot 续写数学,N≥500 题)**:
- **非零(>2δ,δ=1.4/√N≈6.3pt@500)**:仪器存在,产出半有信号。
  进入 L2 设计(SFT → pass@k 作为 30B 构建的转向量)。
- **零或 <2δ**:格式桥接不动,base 在 3.24b 仍不产出。
  进 L2(SFT 是唯一路径);L2 仍零 → **200M 规模上推理产出无仪器,
  这是本轮最重要的结论**——它改变项目可测性,先于可实现性。

**不跑的**:zero-shot 生成数学在 base 上(SKIP,格式+能力混淆,0/500 已证)。
SKIP 的是 zero-shot base,不是产出本身。

**判决(2026-08-30,p324 落盘后)**:零分支命中。3-shot 续写数学 **1/497 = 0.2%**,
δ=6.3pt,仪器阈值 2δ=12.6pt —— base + few-shot 在数学上读零。第二条腿:
base 3-shot 代码 **0/497 = 0.0%**(fb,code_fewshot_p324.log)。两个域都在
仪器阈值以下,**base 模型的推理产出在当前配方下无仪器**。

零是有效的,不是退化:答案成形率 63.6%(模型持续产出带 \boxed/答案是 的连贯
中文数学文本),但答案错——生成在续写 demo 的模式,不绑定目标题。这是能力/
指令 gap,不是格式 gap,不是 token 乱码。dtype 已验证无污染(44 直接测量
logit diff 0.00000;A_log/dt_bias 训练时始终是 bf16,推理 .to(bf16) 是 no-op)。

SFT 轴干净读数(2026-08-30 终):`code_zh.py` 在 `ckpt_sft_p324_v2.pt` 上
**11/500 = 2.2%**,仍在 12.6pt 仪器阈值以下——**读零**。11 道对题全是
最简单模板(9 道列表求和均值、2 道两数和差、1 道列表查找),单模板模式
补全,不是泛化。包干净:de 的 `sft_pack_uncontaminated` 对
`code_holdout_500` 0/36,加 fb 手工逐 token 探针 0/40。v1 出自被污染的 pack

bf16 累加序不同,种子噪声量级,搬不动 13 个点,但限定在此)。
post-SFT math_zh 是退役指标(30% containment),不参与判决。

demo-count sweep(--demos 0|1|3)终:code 三臂 0-shot / 1-shot / 3-shot =
**0/497 / 0/497 / 0/497 = 0.0%**(空续 2.2% / 0.0% / 1.6%)——**demo 干扰假设
在 code 上证伪**:0-shot 不优于 3-shot,失败不是 demo 回溢,base 在此 regime
无代码生成,给不给 demo 都一样。
math 三臂 accuracy 0.4% / 1.4% / 0.2% 全部地板,2δ=12.6pt,
**三数之间任何差都不可解释**(包括 1-shot 1.4% 高于另两臂);accuracy
判据标**地板,不可判读**,预注册文本保留不删(删 = 事后改判据)。成形率读数:
math 0-shot 25.4% / 1-shot 53.5% / 3-shot 63.6%,code 97.8% vs 98.4%(+0.6pt),
统一机制见下。

**零的机制相反(2026-08-30,fb 点出)**:base 0-shot 空续仅 2.2%——97.8%
在写代码形状的文本,全错(**形状对、内容错**);SFT v2 no-fence 87.8%——
连 ```python fence 都不稳定出(**形状退了**)。两个都读零,但 **SFT 在代码
上让形状变差了**:SFT 教的是 ChatML 问答形状,代价是续写代码的形状。
"SFT 后形状单调变好"在唯一测过它的地方已被证伪——一个已经有反例的
规律不能当默认。**SFT 对格式的作用方向已在 code 上测出为负;是否在 L2
上同样为负未测,因此 L2 的 prompt 格式单独验证**(反例是事实,外推是
外推,分开记)。

**demo 增益机制(2026-08-30,b0 的 math 数并入,写成预测不是总结)**:

| 域 | 无 demo 形状率 | 1-demo | 3-demo 形状率 | Δ(0→3) |
|---|---|---|---|---|
| math(答案成形) | 25.4% | 53.5% | 63.6% | +38.2pt |
| code(代码成形) | 97.8% | 100% | 98.4% | +0.6pt |

**预测:任何域,成形率起点越高,demo 增益越小。** math 侧(25.4→53.5→63.6,
单调、边际递减(0→1 +28.1pt,1→3 +10.1pt)、跨度 38 点)是机制的**证据**——
一条剂量-反应曲线,能证伪机制(1-shot 反低于 0-shot,或增益线性不饱和)。
code 侧成形率 97.8–100% **处于天花板,无量程,不能确证也不能证伪**,仅说明
起点已高——和 accuracy 贴地板同病:一个撞天花板一个贴地板,都没有分辨率。
机制的下一个检验要找一个成形率起点在中段(30–70%)的域。

**退化重复率(2026-08-30 固化,fb 立指标,b0 复算+math 侧)**:8-gram 出现
≥3 次即判退化(空白分词;最小长度守卫 = 够构成一个 8-gram,即 n——曾用过 3n,
会漏掉短的退化生成,已废;参数进 config 不进散文)。

| 臂 | code | math |
|---|---|---|
| base 0-shot | 25.4%(126/497) | 16.9% |
| base 1-shot | — | 9.3% |
| base 3-shot | 6.6%(33/497) | 8.9% |
| SFT v2 greedy(zero-shot) | **55.8%(279/500)** | 未测 |
| SFT v2 t=0.8(zero-shot) | 17.0%(85/500) | 未测 |

读法(两句,方向相反):

1. **格式类指标(围栏率、退化率)在贪心下是解码器的性质,不是模型的——报告
   必须带温度。** SFT greedy 55.8% 是 base 0-shot 25.4% 的两倍多,但换 t=0.8
   就掉到 17.0%,**低于 base 0-shot**——"SFT 把退化翻倍"只在贪心解码下成立,
   那个循环不是 SFT 装进模型的病,是贪心解码在这个模型上的表现。
2. **能力类指标(准确率)不受解码器影响,而且现在更稳。** t=0.8 准确率 0.5%
   vs greedy 2.2%,两个都在地板;循环消失了,答案还是错的——**那个循环没有
   藏住任何东西**。"准确率是坏解码器造成的假象"这个怀疑查过了,不是。

demo 压制退化保留独立读法:demo 和采样都能打断循环,而 SFT 不能——三者作用
在同一个地方(贪心的确定性吸引子),这本身是证据。3-shot 两域可比
(math 8.9% vs code 6.6%)。

**为什么这个指标该在面板上**:它一直可测,却躲了五个 checkpoint——面板只记
accuracy,而 accuracy 在这个规模读零。**永远读零的指标等于没有指标**(gate
文档"一个 PASS 必须说出验了多少东西"的度量版)。363c491 曾把退化归因为
"content, not format";那个归因站不住,只是因为退化从来没被测过——SFT 语料
89% 答案带围栏(模型见过格式),退化率照样翻倍。该归因已进 guard_phrases。
教训(本年第四次):一个指标的配置比它的名字多——n=8/k=3 不足以定义它,
最小长度守卫也是定义的一部分,fb 首版没说出来,差了 3 条真阳性。

**已知天花板**:`code_zh.py:128` 存的是 `gen[-300:]`(字符),现在量的是生成
**尾部**退化——先答对再啰嗦的模型会被误判。当前 accuracy 2.2%,偏差可忽略;
能力上来后偏差变大,那时改全量存或在线计算。跨语言注记:300 字符窗口在各
语言里 token 数不同(中文更密),跨域绝对值带窗口密度混淆;域内对比
(SFT-vs-base、demo 剂量)不受影响。

复算注记:fb 首版报 base 0-shot 24.7%,差异查明——首版带 `len≥3n` 下限守卫,
漏掉 3 条不足 24 词但确实重复的生成;去守卫后 25.4%(126/497)为口径值,
其余三数精确复现。

**结论(2026-08-30,fb 写死)**:200M 在此 regime 无可测代码生成——base
三个剂量点全零、干净 SFT 也读零。L2(pass@k)是唯一剩下的路径,而 SFT
让形状变差这个反例意味着 L2 的 prompt 格式必须单独验证,不能沿用 SFT
的假设。

## 3. 可验证性不对称(fb 的 Q3,确认并写死)

数学/代码答案可执行验证——对就是对,错就是错,不需要裁判,不需要相似度。
这带来两个后果:

1. **标签无 MDE**:N 题精确匹配的误差是二项的 δ=1.4/√N(p=0.5 最坏情形),
   500 题 → 6.3pt,1000 题 → 4.4pt。没有 seed 方差进标签(执行是确定性的)。
   seed 方差仍在模型侧(不同 seed 不同模型),但单次测量的误差是二项的,
   比 NLL 的 σ̂=0.0516 锋利得多。
2. **A/B 更便宜**:推理数据配比的 A/B 用 pass@k,误差是二项+seed 方差,
   大概率比 NLL A/B 锋利。可验证标签移除了裁判/相似度问题(那是质量头沉没的原因)。

## 4. §8 形态迁不迁移(fb 的直接问题)

**形态逻辑迁移,具体指标不迁移。** §8 的四形态(A 容量/B 配比/C 齐动/D 不可读)
本质是"判别半饱和时产出半动不动"——这个逻辑与目标无关,推理版照用:
- pass@k 随 D 动、判别饱和 → 容量型;
- 判别动、pass@k 不动 → 配比型(或容量天花板);
- 都不动 → 不可读。

但 §8 的指标(lambada L2/O1/GAP)是表达能力的,不是推理的。**§8 不替换,
加兄弟**:推理版需要自己的产出半(L1/L2 的 pass@k)和判别半(math_v2_like +
代码判别),形态逻辑照抄。**当前阻塞:推理的产出半不存在(base 上 pass@k=0),
形态无法触发——L1 是前置条件。**

## 5. 代码侧的缺口

代码判别仪器(L0')不存在:需要一个带测试的代码题数据集(HumanEval/MBPP 类),
测模型是否给执行通过的完成更高似然。这是 3b/44 的数据活,不是我的读法活——
但**30B 构建要转向代码推理,这个仪器和 L1 数学一样是前置条件**,并列优先级。

## 6. 代码判别仪器规格(2026-08-30,fb 要)

**形状**:逐题胜率——每题有 prompt + ≥1 执行通过的解 + ≥1 执行失败的解,
测模型给通过解的 per-token NLL 是否低于失败解。胜率 = 通过解 NLL 更低的题占比。
这是 math_v2_like 的代码版:标签来自执行,不是裁判。

**已知答案案例(两层)**:
- **仪器验证层(易扰动)**:取正确解,单算子变异(`+`→`−`、`<`→`>`、`=`→`!=`),
  变异解必挂测试。模型应在 >90% 的题上偏好未变异解(同一代码差一个 token)。
  不偏好 = 仪器坏了,不是模型差。自动化变异,零人工。
- **转向量层(难扰动)**:变异算法(错边界、反条件、漏 edge case)——模型生成的
  失败解(采样 K 个、执行、取挂的)是最便宜的来源,但可能错得太明显。
  难扰动给 headroom,易扰动只验证仪器。
  **冻结纪律(fb 2026-08-30)**:模型生成的失败解随模型改进而变难,
  3.24b 的分数与 30B 不可比(对手在动)。干扰子集从**一个 checkpoint 冻结**,
  跨 checkpoint 复用,不重新生成。

**分辨率**:二项 δ=1.4/√N。N=500(MBPP 量级)→ 6.3pt;N=1000 → 4.4pt。
math_v2_like 在阶梯上动了 11pt,6.3pt 够转向用。

**失败模式(预注册)**:
1. **扰动太易**:失败解有语法错误或显然错 → 胜率饱和 ~100%,无分辨率。
   已知答案层就是查这个的。
2. **长度/分词混淆**:通过/失败解长度不同,总 logprob 有偏。用 per-token NLL,
   或长度配对(math_v2_like 的等长扰动纪律)。**但 per-token 不够(fb)**:
   代码在中文 BPE 下分词碎,失败解与通过解的碎裂程度可能系统性不同——
   比较前先查一对候选的 token 数是否相近;系统性不同则 per-token 归一化失效,
   需长度配对或按碎裂度分层。
3. **训练污染**:题在训练语料里 → 测的是记忆不是能力。用留出题
   (holdout_v2 纪律,sha1 切分 + 验收扫描)。**3b  owns 仪器(fb)**:
   MinHash 已知答案已验证(296/296 召回,0/72 误报),留出切片在指纹之前切,
   与 LAMBADA-zh 留出同序(两次独立扫描验证过)。
4. **天花板**:胜率 >95% 后动不了。math_v2_like 阶梯动 18pt(76.69→94.69)后耗尽——
   近天花板的指标分不出"好改动"和"极好改动",而这正是转向量的全部工作。
   **headroom 是设计参数,不是事后发现的(fb 立规)**:代码仪器从难扰动起步。

**swap 稳定性**:通过/失败解顺序互换,胜率应不变(math_v2_like 已验 0.9625/0.9625)。

## 7. 可验证答案的经济学(fb 要求记为事实)

**在答案可执行验证的任务上,配比 A/B 可能买得起——同样的 A/B 在 val NLL 上买不起。**
标签误差是二项的(δ=1.4/√N,500 题 6.3pt),seed 方差不进标签;
val NLL 的 σ̂=0.0516 杀死了 KDA A/B、让 AttnRes campaign 买不起。
A/B 仍有模型 seed 方差,但标签是锋利的。**这是本回合约束的反转:
转向推理后,可测性上升,不是下降。**

## 8. 独立性判据(2026-08-30,用户指令"维度必须独立且有区分度",fb 实测相关矩阵后)

fb 的矩阵:L2/O1/O5/math_v2_like/dloss 两两 r=0.90–1.00(n=6),CE 是噪声,
mp(0.48–0.72)是唯一带 val loss 没有的信号的条目。**裁决:fb 的弱读法成立——
它们在 D 轴上冗余,不在一般意义上冗余。**

**为什么弱读法对且够行动**:六点只在 D 上不同。沿单一缩放轴,任何随规模改善
的量都与其他随规模改善的量相关——矩阵无法区分"冗余指标"和"恰好一起缩放的
不同能力"。但 **D 轴决策只需要 D 轴冗余**:一个指标沿 D 是 val loss 的近似确定
函数,它对 D 决策就不携带信息,无论它测的是不是同一种能力。弱读法精确等于
行动所需。

**矩阵不许可什么**:不许把它们作为能力度量退役,不许声称它们测同一件事。
反例就在面板里:L2 与 O1 沿 D 相关 0.94,但它们的**差**(GAP)是表达能力的
转向量——两个相关指标可以在对比中携带独立信息,相关矩阵看不见对比。

**n=6 的 CI 很宽**(r=0.90 的 95% CI 约 [0.36, 0.99]):"一个维度"是提示不是
结论。行动(降级 D 转向声音)对 CI 稳健,因为只需"沿 D 近冗余";GAP 无论
如何保留。

**面板重组(按能力轴,不按格式)**:
- 语言建模:dloss(D 轴主指标)
- 表达:GAP(L2/O1 降为输入,不再独立发声)
- 数学判别:math_v2_like(沿 D 近冗余,保留为数学轴代表,不作 D 转向)
- 句法:minimal_pairs(唯一验证过的独立信号)
- 知识:C-Eval 死(地板,无区分度)
- O5:与 dloss r=1.00,纯冗余,降级为诊断

**新指标准入判据(e1 的推理指标、44 的代码 eval,完工前需要)**:
席位靠**在非 D 轴上分离**赢得,不靠沿 D 相关:
1. **配比轴**:10× 同配比对照臂 vs 构建臂——mix 变而 D 不变下分离 = 独立。
2. **训练阶段轴**:base vs SFT——SFT 动而 val loss 不动 = 独立。
3. **架构轴**:attn_every A/B(3.24b 重问)——架构分离而 val loss 不分离 = 独立。

操作化:先对 D(或 val loss)回归取残差;残差是噪声 → D 冗余,再查非 D 轴
分离。**D 冗余且从未在非 D 轴上测过 = 从 D 面板降级的候选,不是删除候选。**
代码判别和 L1/pass@k 沿 D 会和一切相关——预期的,不是缺陷;席位由能力轴
覆盖保证,独立性检验决定转向声音,不决定存在。

## 9. 上下文长度(NoPE 探针,2026-08-31,fb 派活)

**架构背景**:seq=4096,NoPE(无 RoPE、无学到位置嵌入,位置全靠 KDA 状态携带);
1024 滑窗 2026-08-30 已删,注意力是 4096 上的完整因果。三层 gated MLA 机械上
与长度无关,九层 KDA 是固定大小状态——两条腿在超长时的行为可能相反。agent 循环
每轮吃 调用+工具输出+继续,多轮后 4096 见底,可用预算是 30B 设计约束。

**预注册(脚本 commit 847c8da,跑之前)**:配对 ΔNLL——同一 holdout 行 b 跑两次
(fresh 4096 vs 接在 a 后面的 8192),Δ[p] = NLL(8192, 4096+p) − NLL(fresh, p)。
因果不变性使这是纯长度对比。读法:seam Δ(距离 4096-4352)> +0.10 nat → 硬边界;
≤ +0.10 且随距离上升 → 平滑退化。4096 内:256-token bin 曲线,有效预算 = bin NLL
持续超最低 bin +0.10 nat 的首个位置。

**结果(ckpt_p324,256 对,GPU 7)**:

- **4096 之外:平滑退化,无硬边界。** seam Δ = **−0.198 nat**(4096 额外上下文在
  接缝处反而帮 0.20 nat——模型在用上下文,即使距离没见过);斜率 **+0.10 nat/1024
  token**,尾部(7936-8190)+0.104 nat。零交叉点 ~6.2K:携带上下文有用到 ~6K,
  ~8K 打平,再远有害。
- **4096 之内:全标称可用。** 冷启动 bin(pos 0-255)3.72,稳态 3.46-3.57,最低
  3.4575@3072-3327,无持续上升——有效预算 = 4096,没有隐藏缩短。
- 8192 跑的 2048 窗口 NLL:3.52 / 3.49 / 3.51 / 3.64。

**对 30B 的支撑(fb 已用于决策)**:训练端不加长——语料按 mix 加权 >4096 的文档
只有 4-5%(code 0.4%),doc_mask=True 下 8192 只是塞更多独立文档,注意力 FLOPs
翻四倍不买任何更长依赖;**30B 训在 4096 不动**。推理端可超出、代价 0.1 nat/1024
——正是需要的那一半。唯一可能要 8K 的是 agentic 轨迹本身(一条多轮对话是一个长
文档;44 实测 code 循环 p90 1729 token/轮,三轮 5187),等真实轨迹渲染出来再算,
不预付。

**未测**:两条腿(KDA vs MLA)各自的退化归因——整体模型平滑,分层消融是后续。
