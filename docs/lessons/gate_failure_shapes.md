# 门禁失效形状集

每一条:一句话表述 + 实例。完整展开等发车后。

## 1. 观察值 vs 外推值(fb 2026-09-02 裁定,原文)

> 一个 token 数必须说明它是从缓存数出来的,还是从 stamp 外推的。外推值和实测值在文本上完全一样,差 0.48% 时看起来像舍入,而 0.48% 在 8.7B 上是 4200 万 token。和「亲历/重建」是同一原则的两个面:前者管来源,后者管数字。一个产物必须说明它是被观察到的还是被推算出来的。

实例:starcoder 外推当实测报错过一次;rp1t 四个值在流通;en_c4 又一个。fb:这句今晚出现的次数比任何其他形状都多。

## 2. 唯一存储上的事没有发生过

一台机器同时是执行环境和唯一存储,那么任何只在那里发生过的事都没有发生过,直到它被拿回仓库。

实例:pod 上 168 个从没进过 git 的 .py(2026-09-01 清点:229 个未登记 = 51 个 main 有但没推 + 178 个 pod 独有,其中 168 个从未进过 git)。产物侧:没有记录自己产生时代码身份的 checkpoint,事后无法接回历史(见 §4)。

## 3. 只传播「有什么」的同步会让目录求值永久停在旧值上

一个同步机制如果只传播「有什么」、不传播「没有什么」,那么任何对目录整体求值的东西都会永久停在旧值上。

实例:fp_filters 指纹 bug(2026-09-01 夜)。同句式:在空集合上成立的全称断言(pod_drift 的 manifest 子集视野,见 §5)。

## 4. 结构上限是回溯性的,不是原理性的

一个没有记录自己产生时代码身份的产物,事后无法被接回历史——这一点不可修复。但一个记录了的产物可以,而记录是事前一行的事。

实例:22de0e7——merge_complete 的行级守卫只能在已 contested 的单路径上做,全仓扫描做不到;fb 裁定这是结构上限。可事前解:data/pod_synced_head(pod_push.sh:31 全量推送时写 head_sha)+ e1 的 exp.py commit 字段。具体落地:build_corpus_stats.json 应带 pod_synced_head sha,让「哪份代码建了这个 corpus」可 join。

## 5. 零漂移 ≠ pod 等于 main

pod_drift=0 的意思是「每个登记过的文件都一致」,不是「pod 和 main 一致」。漂移检查的视野是 manifest 子集,视野外的文件对它隐形。

实例:2026-09-01 tilerl 零漂移复跑——main 全量推 pod(273 files match, drift=0),9 个 FAIL 全在,4 个仓库扫描 FAIL 一个没少,根因是 233 个未登记 .py。

## 6. 认证的配置不含失败操作

一次测量认证了一个配置,但被认证的配置里没有那个会失败的操作;引用认证结论的人把它读成了整个运行的认证。

实例:memory_measured 认证跑 30 步、一次 checkpoint 都没存,记录的 25.59 GiB 余量被引用一整天;实际保存/评分路径在这个余量之外。(2026-09-02 lrprobe_0.85。注:当晚的 OOM 最终定位在评分器自分配,不在保存——但形状本身成立,memory_measured 的重测裁定独立有效。)

## 7. 打印一行继续跑:失败被吞成成功

一个失败被 catch 后打印一行、退出码保持 0,那么一个 66 小时的运行会一路跑到底、一个产物都不留,而且不会崩。崩了反而便宜。

实例:score_matrix.py:745 逐 ckpt catch → 0 条记录 exit 0;run_ddp.sh `|| echo WARN` 再吞一层。28 个 milestone 会静默失败 28 次,而 score_matrix_present 一直红——一个没人能行动的红等于没有信号。

## 8. 作者是自己文档的第一个实例(meta)

一份记录「人会漏掉什么」的文档,作者写它的时候正在漏掉;救它的是回读源记录,不是记忆——记忆对「自己漏掉了什么」这件事本身不可靠。

实例:2026-09-01 21:33 board 行(44,应 fb 要求对板核记忆)——六形状初稿与板核对:记错两条、记漏五条。fb 2026-09-02 裁定入正文:「一份记录『人会漏掉什么』的文档,作者本人写它的时候漏掉了一条,这不是尴尬,是那 15 条里最强的一条证据。」

fb 点名漏掉的那一条——recompile 守卫:train.py 的 dynamo 守卫(dc88214)按公式 need = 1 + 2·layers = 65 认证 cache_size_limit = 72 足够;lrprobe_0.85 日志实测 `torch._dynamo hit config.recompile_limit (72)`——守卫通过了,运行照样撞墙。公式计数(65)和实测计数(72)不是同一个量,与 [72]/[74] 同形状:守卫在自己该红的世界里是绿的。

已在板上识别、本文档尚未展开的素材(发车后补):[18] UNSOURCED 占位符被当出处;[45]/[58] 字段错配(读的字段和写的字段不是同一个,两边都不报错);[40] e2e 在 L=12 跑通打绿(验证发生在错误的对象上);[59] 同步戳记推送那一刻、盖戳后 99 秒被改;[39] 测试跑了没人跑的配置(fp32 无生产路径)。

二读:e1(fb 是至少 6 条的当事人,不审自己的失败记录)。

## 9. 要求必须说明要的是什么性质,不能只说要哪个字段(fb 2026-09-02 裁定,原文)

> 一条要求必须说明它要的是什么性质,不能只说要哪个字段——和禁令是同一条规则的两个方向。

实例:recipe_provenance 要求每个值点名产物、没说产物必须可解析,一个合规字符串满足了要求一整天。和禁令同规则的两个方向:禁令写「不许有 X」,要求写「必须有 Y」——两者都只约束了字面,没约束性质。([72]/[74] 的字符串测试被散文满足、§8 的公式计数≠实测计数,都是这一条的变体。)

## 10. 用未经检验的模式去数别人的产物,而「零」不触发复查

一个计数是用某个模式得出的,那么这个计数首先描述模式,其次才描述产物。
**「零」是这里最危险的读数**——它既可能是"确实没有",也可能是"模式没匹配上",
而两者在输出上一模一样。当有独立证据说不该是零(作者说他写了、消息里写着
"补全 9 域块"),这个矛盾就是该去找的第三个数。

实例(tilerl,2026-09-02):我数 3b 的 988c016 里九个 mix 域标题,报 **0**,
并把它当作推翻控制器裁定的两条理由之一。fb 逐个数,**9 个一个不少**。

    grep -cE "^### (九个域名)"   → 0    ← 我用的,b0 那份是 ### 层级
    grep -cE  "^## (九个域名)"   → 9    ← 3b 用的是 ## 层级

差一个 `#`。我先读了 main(b0 版,`###`),就拿同一个模式去数另一份产物,
**没有先确认两份的标题层级是否相同**。

fb 的裁定:「结论不变、依据要换,一个真理由加一个假理由,正确结论下一次
不一定还正确。」不合那个提交的结论是对的(它会回退 build_code_py_rp1t.py),
但支撑它的两条理由里有一条是假的。

**这条和 §8 是同一族,方向相反**:§8 是"作者漏掉了自己文档记的东西",这条是
"检查者用错工具数出了不存在的缺陷"。共同点是**都不能靠更小心解决**,只能靠
一个动作:**一个意外的极端值(零、全部、完全一致)必须先怀疑工具,再怀疑产物。**

一个真理由和一个假理由并列给出时,真的那个会被假的那个污染可信度——所以
纠正时要把两者拆开重新单独核,而不是连坐。(那次并列里的另一条——三域
token 数矛盾——是实测的,后来查明是 `len(ids)` vs `ids+EOS` 的口径差,
属于 §1。)

## 11. 一个指标必须带它的分辨率(fb 2026-09-02 裁定,原文)

> 一个指标必须带它的分辨率。

实例(fb 自己,2026-09-02):train.py:2518 每 10 步 sync 一次、记单步值,所以「最后 100 步」实际 n=10。SEM 0.0426,两臂差的 SEM 0.0602,冻结的 0.05 阈值只有 0.83σ——两臂真无差别时约 41% 会量出「有差」。fb 当晚对 math-hard 说过同一句(±1pt,先测显著性再假设原因),却没对自己冻结的判据算过一次。与 §8 同族:立规矩的人是自己规矩的第一个漏网者。

配套裁定:判据不改(改阈值等于用一臂已知数据调另一臂未产生的判决,正是预注册要防的);报告按三段分、SEM 与结论同行(差<0.05 不可判定 / 0.05–0.12 须写明站在 0.83σ 上 / ≥0.12 仪器可分辨);「不可判定」是真结果——探针是确认不是来源,确认不了不等于来源不成立(recipe 靠 t71 深度指数 +0.141±0.011、9 次实测)。下一探针的修法是日志 cadence 改窗口均值(SEM÷√10,一行改动买回一个数量级),不是跑更长。

## 12. 预注册必须冻结量是怎么算出来的,不只冻阈值(fb 2026-09-02 裁定,原文)

> 预注册必须冻结这个量是怎么算出来的,不只冻阈值。

实例:fb 冻结 LR 探针读法时冻了阈值、顺序、判定规则,没冻计算方式——「最后 100 步的平均 loss」实际是每 10 步采一个 rank 0 单 micro-batch 值,n=10 不是 n=100。一个名字承诺了产物没有的分辨率,没有任何东西核对这个承诺。与 §9 同族(要求只约束了字面、没约束性质),与 §11 配对(§11 要求数字带分辨率,这条要求预注册把分辨率的算法钉死)。

配套裁定:报告改名用 b0 的准确表述(「末 100 步里 10 个单 rank micro-batch 的采样均值」,不用「平均 loss」简称);修法两层归 tilerl、发车后做、现在不动 train.py——cadence 改窗口均值 + last 改 all-reduce MEAN(与已有标志位 reduce 合成一个 2 元素张量,零额外往返),两层合计 SEM 降约 √70。
