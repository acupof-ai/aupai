t49 pretokenize throughput (2026-08-31, 44; /tmp/bench_pretok.py on the pod, 180 CPUs)

Method: exact replication of train._domain_seqs's tokenization path (same shard
glob, same random.Random(Cfg.seed=42) shuffle, same encode() -> one
<eos>-separated int32 stream). 8-process run splits the shuffled doc list into
contiguous blocks, streams concatenated in worker order -> element-identical
stream (stream_sum matches both runs of each domain). Thread budget held equal:
RAYON_NUM_THREADS=180 for 1 proc, 22 per worker for 8 procs.

Load + shuffle is 1.8-4.2s; save + stamps <= 6.3s. Neither is material.

Projection for the stage-1 corpus (~15B tokens):
  1 process (pretokenize.py as written):  66 min (wiki rate) - 102 min (math rate)
  8 processes (this driver):               9 min (wiki rate) - 14 min (math rate)
  Rate is content-dependent (math's denser markup tokenizes ~35% slower per
  byte than wiki chat); the stage-1 mix spans both regimes, so the range stands.

Critical-path verdict: TOKENIZATION IS ON THE CRITICAL PATH TONIGHT IF
pretokenize.py RUNS AS-IS (single process, ~1-1.7h for 15B). With the 8-process
driver it is ~9-14 min -- effectively off. The driver is /tmp/bench_pretok.py
on the pod; promoting it (or an 8-worker mode in pretokenize.py) is the unlock.
